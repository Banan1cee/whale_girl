### 5.5 finalize is mixed responsibility

`finalize:1779` combines:
- internal timestamp, silence/sticker marker parsing;
- persona-specific text edits, emoji, echo/fight/master tone correction;
- global reply counters;
- assistant message persistence + checkpoint BEFORE bridge sends;
- diary marker expansion, splitting/length policy and turn-state updates.

`chat.before_send` currently runs BEFORE this function; it is not the final byte-level transport interceptor. Plugin text can be rewritten afterward.

GAP: cannot safely reuse whole finalize for an external brain that requests no Whale persona/Whale memory. Must separate business text policy, optional memory commit, and transport-safe processing first.

Streaming generation uses `Bot.generate`, not `_handleOnce` retry orchestration.

## 6. Delivery chains CURRENT (not one queue)

### 6.1 Synchronous ordinary reply

`Gateway.send`:
- no outboundUrl + local: `{ok:true,dryRun:true,local:true}`; actual send occurs AFTER response in Python;
- no outboundUrl + nonlocal: dry-run/stranded;
- outboundUrl: postJson; up to two attempts per bubble, optional sendBubbles; HTTP success is transport submission only.

`chat.dispatched` fires within Gateway before Python receives local response. It cannot prove actual WeChat sending or delivery.

Python `on_message_inner` response handling:
reply validation -> rate_guard -> stickerOnly / voice choice -> send_at or send_text for bubbles -> optional sticker.
Uncertain voice send may suppress text fallback to avoid duplicates.
One text bubble failure cancels remaining bubbles/sticker.

`SenderMixin.send_text` and associated senders coordinate account validation, send policy, paused/dead chats, UI/window state and input protection; transport selection includes background/UIA/keyboard paths. Preserve existing guards when extracting interfaces.

### 6.2 Plugin text/voice and diary

`SDK.sendText/sendVoice -> IPC send -> PluginHost.send -> ReminderService.enqueueNow`.

```text
plugin grant id/hash check
persist reminders item (kind=plugin, delivery=text|voice, status=pending)
/api/reminders/due -> ReminderService.due -> sending
Python ReminderRunner -> permission recheck -> send_text/send_voice
/api/reminders/ack -> done OR unconfirmed (plugin failure, no auto retry)
SDK.delivery -> done mapped to submitted; confirmed=false
```

Queue return `{status:'queued'}` is SDK representation; stored initial status is `pending`.
Plugin jobs bypass ordinary reminder on/off/daily/quiet rules, but not plugin authorization and sender guards.
Diary also uses enqueueNow; ordinary reminder retry rules differ from plugin no-retry rules.
Restart/load/expire paths in ReminderService are part of semantics; never copy only ack logic.

### 6.3 Images/stickers

`PluginHost.send(image)` -> require sticker enabled -> file/type/size processing -> imported image -> StickerService.add -> plugin id/hash on job.

`StickerService`: jobs Map, pending -> claim/gate/cancel/ack; Python StickerMixin/sticker_transport executes and verifies.
Image `confirmed` has stronger evidence than text submitted; do not collapse both into generic “sent”.
Jobs are in-memory; image queue does not promise persistent replay.
Automatic reply stickers may be reserved and carried in webhook response instead of generic background discovery.

### 6.4 Other independent send paths

- care: Python care_watch -> `/api/care/due` -> `/api/care` generation -> sender -> `/api/care/sent` receipt.
- battery notifications: Python battery_watch.
- manual voice/sticker tests: bridge watcher loops + corresponding task endpoints.
- moments interaction/publishing: own claim/gate/complete protocol.

GAP: no universal message task owner / global delivery state machine. Multiple paths share physical sender locks, but have different persistence, retry and receipt semantics.

## 7. Plugin execution CURRENT

### 7.1 Hook composition

`Bot.constructor` creates JavaScriptPlugins + MessagePlugins and wraps them in PluginRuntime.

`PluginRuntime.run`: Wasm (for old hooks) first -> JavaScript with previous outputs -> merge.
`supports(hook)` reports JS support, used for search hooks; not a general feature registry.

Hooks:
- Wasm: received, pre_reply, prompt, generate, reply, before_send, dispatched.
- JS additionally search, search_result, app.start, app.stop, timer.tick, tool.run.

Per-runtime plugins execute in installed ID order. First explicit pre_reply action stops that runtime's loop; JS runtime still executes after Wasm, and a non-pass JS result overrides Wasm action. This is not a single cross-runtime exclusive-owner rule.

### 7.2 Wasm

`services/messagePlugins.js`:
installed grants + hooks + permissions -> per-session chain -> concurrency acquire -> execute -> output validation -> grant recheck -> state atomic write -> result.
history/model.prompt filtered by permission.
Budgets: per plugin 300ms, hook 800ms, message 2400ms; max parallel 2; state 16KiB, max 200 files/plugin; input/output 64KiB.
Failure -> fallback + 30s cooldown. `chat.received` resets scan/budget; dispatched clears budget; not every message reaches either hook.

### 7.3 JavaScript / SDK

`javascriptPlugins.js`:
installed grant/hash/version check -> per-plugin invocation chain -> global slot -> Node worker -> IPC invoke -> validate -> grant recheck -> persist.
Per-plugin serial across conversations; max parallel 2; max installed enabled 16; worker heap 256MiB; configured timeout 100–120000ms, default 30000.
State 64KiB and 200 files/plugin; IO 512KiB; failure cooldown 30s.

`javascriptPluginWorker.js::createSdk` currently exports:
api, capabilities, search, model, send, sendText, sendVoice, sendImage, delivery, paths, context.
`require('whale')` is injected into plugin module. CommonJS, no automatic npm installation.

`PluginHost.call`:
- approved id/hash guard on calls;
- capabilities: API/hook/method/route listing, not readiness/ownership contract;
- model -> r.llm.complete, purpose=plugin (not recursive Bot chat);
- search -> searchService.search(force=true), independent timeout/options;
- api -> same-origin loopback `/api/*` fetch with token, redirects prohibited;
- send/delivery -> queues above.

`search` SDK calls bypass chat.search hook; model SDK bypasses chat.generate hook. Future dispatch must explicitly avoid self-recursion if these become replaceable providers.

API 4 is full OS access, NOT sandbox. SDK is cooperative routing, cannot prevent trusted full-access code from using files/network/processes directly.

### 7.4 Plugin lifecycle / tools / installation

JS `start` -> 500ms reconcile loop: revocations terminate workers; app.start once per id/hash/grant; timer.tick by interval, no invocation overlap if busy; no catch-up guarantee.
stop -> closed, timers/workers/waiters/chains shutdown. Worker shutdown callback is bounded, not unlimited transactional cleanup.
`routes/plugins.js` -> runTool; API 1/2 tool and installation paths also exist in launcher, not all plugin work enters Bot.
`launcher/PluginMarket.cs` + plugin-related launcher views are install/enable/update/consent owners; runtime consumes local manifests/grants/settings.
Compatibility: Api 3 old epoch >=4.1.0; Api 4 >=4.1.2; appCompatibility distinguishes epochs. Do not infer new-epoch compatibility from numerical version ordering.
Update requires renewed enablement. Market validation/provenance and client signature boundaries remain as documented; no “verified safe” claim.

Do NOT implement as `chat.generate -> DSH` and claim all other Whale work skipped.

## 11. Behavioral hazards / questions for next round

1. Pick exactly-once owner per scope; multiple replacement plugins currently have no central conflict resolution.
2. Separate dedupe/message scheduling from Store-dependent Whale memory before bypassing Bot.
3. Decide whether external owner receives raw attachments or existing bridge-derived text; image processing already may incur model cost before takeover.
4. Separate transport protections from persona/business limits; decide which caps are mandatory vs configurable policy.
5. Avoid double-send: external plugin either returns a reply for host delivery OR explicitly submits a job; need ownership/commit contract.
6. Timeout after external side effect cannot imply safe fallback/retry; introduce evidence-aware terminal/unknown semantics.
7. Grant epochs and task identity must survive process boundaries; keep existing late-result discard behavior.
8. Add invocation/message/account IDs without logging real identities/body; context propagation must not leak credentials.
9. Backpressure is layered (Python conversation workers, Bot chains, Wasm slots, JS per-plugin chain); adding another scheduler without consolidating responsibility increases complexity.
10. Preserve old hook semantics via compatibility adapter; cannot silently move chat.received earlier and expose additional private/system/admin content.
11. SDK.api is broad full-access escape hatch; new typed service contract doesn't make old routes stable by itself.
12. Preserve SSE/normal reply parity deliberately, or explicitly declare different contract; current implementations differ.
13. Model replacement scope: chat-only vs all consumers (search routing, reminder parsing, diary, memory, digest, moments, SDK calls) must be explicit.
14. Background feature replacement requires avoiding duplicate built-in timers; start services by selected ownership rather than always-start constructors.
15. If new capability manifests/settings are added, launcher and separate market validators must both understand them before public distribution.

## 18. Voice crosses BACK into EXE S

Critical topology correction: voice is not only Node -> Python -> WeChat.

```text
Python send_voice_reply
  -> group/account/send-policy checks
  -> voice_reply.deliver
  -> write data/voice-send-jobs/<id>.json
  -> WhaleLauncher.exe --voice-reply-job <path>

  -> atomic .go
  <- .result or timeout/cancel
```

- Synthesis happens before acquiring physical send slot.
- Before `.go`: failure returns False, ordinary automatic reply may fall back to text.
- After `.go`: recording may have begun; `released=True` is uncertainty boundary.
- Missing result / exception after release returns True to mean “handled or might have sent”, NOT confirmed success.
- Result statuses `sent_unconfirmed` / `uncertain` also return True.
- Finally sends `.cancel`, waits up to 5s; does not forcibly kill worker that may hold recording keys.
- Job artifacts removed only if child absent/exited. Startup/recovery needs distinguish abandoned files from live workers.
- Two synthesis failures can cool down for 5 minutes; send-lock wait bounded 15s, post-release wait bounded 75s; synthesis configured/clamped timeout.

GAP: sender boolean overloads “success” and “must not retry”. Unified delivery contract needs outcome enum, not boolean.

## 29. Memory remaining method checks S / partial mutation caution

`compressAsync`:
threshold -> chunks -> await llmSummary -> applySegment each chunk.
Thrown model error returns failure without applying THAT chunk; earlier successfully applied chunks in same loop are not rolled back.
Thus return counters of zero on later failure are not proof the whole invocation was mutation-free.
Empty summary falls back extractive unless requireLlm.

`prepareSoft`: pending guard -> chunk snapshot -> await summary -> assign pendingSummary.
No deleted/revision/cancellation check appears within these two methods; callers must provide lifecycle protection if needed.
Contrast episode.closeEpisode which explicitly checks chat.deleted after await.

`backup.validateBundle`:
kind/object/type checks, relative memory path restrictions, flat persona filename restrictions.
restoreFrom -> recover old transaction -> before-restore snapshot
-> memory tree OR v1 store prepared for future migration
-> merge settings preserving absent secrets/provider-key map
-> restoreFiles transactional exchange.
Backup import is not authorization to run code; settings/identity restoration still changes future behavior.

`migrateIfNeeded`:
legacy source discovery/signatures -> pending selection (force/dryRun)
-> migrateSessions/merge remapping
-> retain legacy backups -> record migrated signatures
-> synchronize ChatStore.manifest -> atomic manifest write -> import notice.
Manifest write failure intentionally allows retry on next boot; migration merge/idempotency is essential.
readSessionsFile supports legacy store/memory and backup files.store.
Historical per-field conversion branches remain algorithm-specific tests, not generic SDK state migration.

## 32. Whole-map conclusions / next-agent handoff

1. All runtime domains and engineering domains now have an explicit home in this document.
2. Principal receive/process/send/job/config/plugin/lifecycle boundaries have method-level static evidence.

   - raw/canonical ingress vs side-effectful Bot preprocessing;
   - host scheduling/dedupe vs semantic memory coupling;
   - business/persona finalization vs transport safety;
