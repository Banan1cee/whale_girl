# 插件市场适配（whale-girl-plugins）

宿主已只支持 `whale-plugin/1`。市场仓库 `Banan1cee/whale-girl-plugins` 需要按本文改动，才能收录新插件。
本文只写市场仓库要做什么；宿主侧的清单与等级定义以 `src/services/pluginProtocolRegistry.json` 为准。

## 1. 目录

```text
index-v5.json      # 新协议插件目录（新增）
index-personas.json # 人设包，保持不变
packages/<id>-<version>.zip
plugins/<id>/plugin.json
```

旧目录 `index.json` / `index-v2.json` / `index-v3.json` / `index-v4.json` 冻结，不再新增条目；新协议只进 `index-v5.json`。

## 2. 目录条目

`build-index.js` 从 `plugins/<id>/plugin.json` 生成，字段：

```json
{
  "Id": "word-count",
  "Name": "字数统计",
  "Author": "作者",
  "Version": "1.0.0",
  "Level": 2,
  "MinAppVersion": "4.3.0",
  "MaxAppVersion": null,
  "appEpoch": 1,
  "appCompatibility": [{ "appEpoch": 1, "minAppVersion": "4.3.0" }],
  "Description": "统计输入文本的字数",
  "Provides": { "tool.run@1": { "mode": "tool", "scope": "manual" } },
  "Calls": [],
  "DataAccess": [],
  "ExecutionTimeoutMs": 30000,
  "Download": "https://raw.githubusercontent.com/Banan1cee/whale-girl-plugins/main/packages/word-count-1.0.0.zip",
  "Sha256": "…",
  "DiscussionIssue": 0
}
```

- `Level` 取 1–4；`Provides`、`Calls`、`DataAccess` 必须与包内 `plugin.json` 完全一致。
- 下载地址固定为 `main/packages/<id>-<version>.zip`，`Sha256` 由 CI 计算，投稿人不填。
- 目录不写 `Api`、`Hooks`、`Permissions`、`HostAction`；这些属于旧接口。

## 3. 校验器

`validate.py` 加 `index-v5.json` 分支，逐条校验：

1. ZIP 根目录正好两项：`plugin.json` 与入口文件。
2. 入口 = `plugin.wasm`（Level 1–3）或 `plugin.js`（Level 4），与 `Level` 对应。
3. 清单必填字段齐全、无未知字段；`Format` 为 `whale-plugin/1`。
4. `Provides` 的能力在等级允许列表内，`mode`/`scope` 合法；`task.tick@1` 校验 `intervalSeconds`。
5. `Calls` 在等级允许列表内且不重复；`DataAccess` 只允许 Level 3、且必须同时声明 `chat.reply@1`。
6. Level 1–3：`plugin.wasm` 以 `\0asm` 开头，≤512 KiB，导入只允许 `whale_plugin.input_size/input_byte/output_byte`。
   Level 4：`plugin.js` 为 UTF-8、≤8 MiB。
7. `appCompatibility` 1–2 项、同代不重复；`Version`/`MinAppVersion` 为数字版本。
8. 目录条目与包内清单逐字段一致；`Sha256` 与 ZIP 实际摘要一致；ZIP 总大小 ≤16 MiB。

第 4–5 步的允许列表从市场仓库内的 `protocol.json` 读取，该文件由宿主 `pluginProtocolRegistry.json` 复制而来，
两边必须同版本；升级协议时先同步它。

`test_validate.py` 至少覆盖：越级 `Provides`、1/2 级声明 `DataAccess`、错误入口、非 Wasm 字节、
`Calls` 未开放、目录与包不一致、摘要不符。

## 4. CI

- 现有 `validate.yml` 增加 v5 校验，并在 `main` 设为必需检查。
- 拒绝未知字段与未知等级，不要静默跳过。
- 目录由 CI 生成；PR 只允许改 `plugins/<id>/` 与 `packages/<id>-<version>.zip`。
- 旧目录的签名与检测流程保持不变；v5 先做静态校验与摘要核对，动态模拟执行可后置。

## 5. 客户端读取

宿主 `launcher/PluginCatalog.cs` 目前只拉 `index-personas.json`。市场发布 `index-v5.json` 后：

- 增加该目录的下载与解析，映射到 `PluginInfo` 的 `Level`、`Provides`、`Calls`、`DataAccess`。
- 安装仍走现有 `ReadPackage` 校验，并比对目录条目与包内清单。
- 目录尚未存在时保持现状（只显示人设），不要显示空市场。

## 6. 投稿流程

作者交三样：`plugins/<id>/plugin.json`、`packages/<id>-<version>.zip`、可审核源码说明。
PR 目标固定 `Banan1cee/whale-girl-plugins:main`；同一 ID 升版本、作者不变。
CI 通过后合并，客户端刷新即可看到。

## 7. 完成标准

- `index-v5.json` 能由 CI 生成并通过校验。
- 1–4 级各有一个示例包通过安装、授权、运行、停用。
- 宿主能读取目录并安装；旧目录不再产生新条目。
