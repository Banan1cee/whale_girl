# 鲸鲸 4.1.7 朋友圈覆盖测试补丁

适用于鲸鲸 4.1.7 的朋友圈发表故障：提示微信未到前台、相机菜单识别失败，或选图窗口出现后间歇退出。本包仅替换三个朋友圈 Python 文件，保留原来的设置、Key、记忆和聊天数据。

## 覆盖方法

1. 停止内核和桥接，完全退出鲸鲸；托盘里如有鲸鲸，也要退出。
2. 找到实际安装目录，应能同时看到 `WhaleLauncher.exe`、`server.js` 和 `bridge` 文件夹。
3. 备份 `bridge/moments_publish.py`、`bridge/moments_worker.py`；若已有 `bridge/moments_window.py`，也一起备份。
4. 解压补丁，将其中的整个 `bridge` 文件夹复制到安装目录，合并文件夹并替换同名文件。最终路径应为 `你的安装目录/bridge/moments_publish.py`，不要放成 `bridge/bridge`。
5. 重开鲸鲸，启动内核和桥接。界面仍显示 4.1.7 是正常的，本补丁不替换 EXE。

## 复测与回退

- 微信保持登录，打开目标账号主窗口，关闭未完成的选图或发表窗口。
- 在鲸鲸朋友圈页启用发表总开关，点击“立即发表一条”。这会真实发表朋友圈，执行期间请勿切换或拖动窗口、按住修饰键或鼠标按钮。
- 每次等待执行结束再测试下一条；显示“未确认”时先查看微信，避免重复发表。
- 失败时记录失败时间、微信版本和 Windows 版本，并导出新的诊断日志；不要分享整个个人安装目录或明文 Key。
- 回退时退出鲸鲸，将备份的原文件复制回 `bridge`。本次新增的 `moments_window.py` 不再被原版引用，可以保留或移除。

## 修复范围与验证边界

- 按实际前台窗口判断，等待异步恢复，并最多进行一次局部 Alt 解锁重试；用户切走窗口或任务取消时停止。
- 导航返回失败后仍重新识别时间线，继续核对窗口及进程归属。
- 菜单 OCR 失败时允许使用唯一、精确且同进程的菜单项；图片预览不再额外调用 OCR。
- 选图窗口恢复尺寸或控件尚未就绪时，重新读取当前窗口及控件并有限等待；已经进行的输入和发表操作不重放。
- 诊断只记录状态、异常类型与代码位置，不记录异常正文、图片内容或本机路径。

已在微信 4.2.0.53 的本机环境完成一次配图发表并回读确认，另在干净的 v4.1.7 基线上通过 96 项相关自动回归。一次实测成功不代表所有机器均已验证，仍供故障用户复测。

本包不包含聊天图片 AES 密钥提取的兼容修复；该问题与朋友圈发表分开处理。源码及本次构建记录见生成补丁的 GitHub PR / Actions 页面，文件校验值见包内 `SHA256SUMS.txt`。
