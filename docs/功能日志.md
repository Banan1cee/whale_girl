# 功能日志排查

在启动器「诊断」查看内核日志，「微信桥接」查看桥接日志；诊断时取消“仅错误”过滤。
本次新增信息使用 INFO 级别，不需要打开 DEBUG。

## 搜索 `[search]`

- `decision=skip`：看 `reason`。`disabled` 为联网关闭，`empty_input` 为无正文，`router_not_needed` 为没有命中联网条件。
- `router_failed_keyword_fallback`：模型路由失败，但规则判定仍需搜索。
- `stage=filter`：`parsed` 为解析到的候选数、`relevant` 为相关结果数、`rejected` 为被相关性过滤的数量。`parsed=0` 也可能是页面变化或反爬，不应认定网络上没有答案。
- `stage=result`：`stale` 为时效淘汰数、`selected` 为最终保留数，`sources` 是来源域名。为保护隐私不写检索原话、标题或摘要。
- `stage=failed`：错误类型、代码和 HTTP 状态。`deadline_exceeded` 为本轮预算已耗尽。
- “联网资料已注入提示词”：结果已交给模型，不能据此断言模型采用了每条资料。
- `[pipeline] result=skip`：消息在前置规则处被忽略，没有进入搜索/发送阶段，查看该行 `reason`。

## 语音 `[voice]`

`disabled` 关闭；`chat_type_disabled` 不允许当前私聊/群聊；`user_requested_text` 用户要求文字；
`explicit_voice_request` 明确要语音；`probability_hit/miss` 概率命中/未命中；
`error_or_command_reply` 为报错/命令回复。
`result=text_fallback` 表示语音准备失败，已改走文字；
`voice_may_have_sent` 表示可能已送出语音，为避免重复不再发送文字/表情。

## 表情包 `[sticker]`

`no_category_or_demand` 未获得可用分类/发送要求；`job_in_flight` 同会话已有任务；
`no_usable_image` 图库没有可用图；`reserved → sending → ack` 通过同一 `job` 串联。
回执 `reason` 区分超时、草稿、账号、目标会话、窗口、开关和媒体文件；
`unconfirmed` 表示未确认，不是成功，也不会自动重发。
总开关关闭遵循既有约定，不输出表情包日志。

## 朋友圈 `[moments]`

桥接日志只记录 `朋友圈读取失败 type=…` / `朋友圈通道异常 type=…`，并明确是哪个异常类型；
不写正文、昵称或关键词。启动器页面的任务状态（超时、账号不符、结果过期）直接显示在操作结果行，
接口结果只在内存保留五分钟，不落盘。

## 日记 `[diary]`

- `日记生成成功：mode=auto|manual messages=.. chars=.. delivered=queued`：日记已落盘；`delivered=queued` 表示同时加入了发送队列。
- `日记生成失败：type=.. code=.. status=.. detail=..`：模型、磁盘或配置问题；不会打印日记正文。
- `日记发送入队失败：..`：日记已保存，但没能加入主动发送队列。
- `日记时间配置不合法：..`：`diary.time` 不是 `HH:mm`，自动日记不会运行。
- `读取日记目录失败` / `清理日记临时文件失败`：文件系统权限或临时文件占用；不影响下一轮。
- `[diary] start enabled=.. time=.. tz=..`：启动时的调度口径。
- `[diary] skip day=.. reason=exists file=..`：今天已有文件，自动任务被去重。
- `[diary] empty day=.. reason=no_owner_session|no_chat_today`：没有主人会话或当天没有聊天。

## 主动搭话 `[care]`

- `[care] due=true|false reason=.. target=master|group|other|none windows=N gap=.. sent=..`：
  桥接每轮来问时记录一次判定结果；不打印 wxid 和搭话正文。
- `[care] generate mock=.. fallback=.. len=..`：生成搭话内容的长度和是否走内置台词。
- 生成失败会带 `type / code / detail`，不再只有 `err.message`。

## 提醒 `[reminder]`

- `[reminder] add id=.. chatType=.. dueAt=.. textLen=..`：新提醒落库，不含提醒正文。
- `[reminder] enqueue id=.. kind=.. chatType=.. textLen=..`：日记等主动内容进入发送队列。
- 提醒到期、回执、取消由 HTTP 路由记 INFO：`提醒到期 N 条` / `提醒回执：done|retrying|failed|expired`。

## 定时任务 `[scheduler]`

- `scheduler.add name=.. kind=every|at intervalMs=.. nextAt=..`：任务注册。
- `scheduler.cancel name=.. kind=.. runs=.. skipped=..`：任务取消。
- `scheduler.skip name=.. reason=running`：上一轮没跑完，本轮跳过。
- `scheduler.done name=.. kind=.. ms=.. runs=..`：一次性任务或超过 50ms 的慢任务。
- `定时任务失败 name=.. runs=.. type=.. code=.. detail=..`：任务抛异常，其它任务不受影响。
- 启动器「状态」里也能看到 `scheduler` 列表：下次时间、上轮错误、运行/跳过次数。

## 配置与时间 `[config]` / `[diary]`

- `设置接口保存了配置：a、b`：启动器改配置成功；`config.json 已重新加载` 表示手动改文件已生效。
- 配置读取/监听失败会带 `type / code / detail`，并明确说是否继续按旧配置跑。
- 时间字段保存时会规范化：`9:00` → `09:00`，`09:00~12:00` → `09:00-12:00`；
  非法时间段/时区会被拒绝，不会静默退回默认值。
