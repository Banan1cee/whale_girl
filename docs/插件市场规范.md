# 鲸鲸插件市场规范

## 1. 操作入口

- 插件必须在「插件市场 → 已安装」管理。卡片提供启用、停用、卸载和设置。
- 插件自己的配置、预览、执行、权限确认和结果必须放在卡片的「设置」里。用户从设置返回市场后，可以继续管理其他插件。
- 插件不得自行往左侧工作台、状态页、系统设置页或托盘添加入口。宿主已有页面可以展示插件提供的内容，例如人格预设列表。
- 启用只登记插件可用。涉及聊天、模型费用、配置变更或发消息的操作，必须由用户在设置里按次确认，或者在未来由宿主提供明确的长期授权。安装和更新都不能视作授权。

## 2. 功能扩展

- 插件可以实现自己的业务逻辑。要影响鲸鲸内核，由宿主提供版本化扩展点。每个扩展点必须声明输入、输出、可更改的范围、授权方式和异常回退。
- 未来可在消息接收、回复生成、发送前、计划任务、设置等位置增加扩展点。作者需要某项能力时，先提交用途和需要读写的数据，维护者审核接口后再开放。
- 市场包不得直接修改鲸鲸程序文件、替换 EXE、加载任意 DLL 或执行安装脚本。确实需要新增内核接口、修改启动行为或替换核心实现时，先走鲸鲸主仓库 PR 和 CI。接口合入后，独立插件再通过市场发行。
- 插件故障或超时，应能停用该插件并回到宿主默认行为。涉及原有用户配置和记忆的写入，必须有可核对的变更范围和恢复路径。

## 3. 权限和数据

- 缺少声明或授权的能力一律拒绝。每项能力独立授权；更新增加能力时，必须重新确认。插件看不到模型密钥、微信凭据和任意本地文件。
- 网络、聊天历史、模型调用和发送由鲸鲸宿主代办。宿主必须核对目标、范围、账号和用户授权。插件直接收到的数据限于当前能力所需。
- 当前 Api 2 开放文本输入输出与手动消息汇总。消息汇总要按次确认，插件只接收汇总结果。如果使用云端模型，鲸鲸会把选中范围的聊天片段交给模型服务商。读取原始会话、定时运行、修改核心配置和自动发送尚未开放。
- 人设插件启用时登记预设。用户在设置里预览并确认应用，宿主按既有人设校验保存。停用会从预设列表移除该条目，已经应用的人设可由用户另选预设覆盖。

## 4. 上架与更新

- 作者提交源码、安装包、版本、兼容范围、所用权限及试装步骤。维护者审核后才把它加入公开目录。
- 插件 ZIP 只允许该类型定义的文件。市场校验固定版本和 SHA-256。新类型放进对应版本的目录，避免影响旧客户端。
- 同一个插件 ID 保持类型一致。更新升版本号，原包保留。安装、启用、拒绝权限、错误回退、停用和卸载都要验证。
