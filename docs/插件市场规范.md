# 鲸鲸插件市场规范

## JavaScript API 4

最低客户端 4.1.2，公开投稿独立 `index-v4.json`，包内仅 `plugin.json` 和 UTF-8 `plugin.js`。
权限明确声明 `system.full`，完整系统能力需用户逐个确认。市场校验、溯源和隔离容器兼容性检测规则见 [Api 4](插件JavaScriptApi4.md)。
保留旧 Wasm 规则，不得将新脚本伪装成旧受限插件。更新提高版本、保留旧 ZIP；同 ID 和作者直接升级并保留配置和数据，新版本停用待确认。

## 分级检测与版本溯源

- 人设预设使用独立 `index-personas.json`，只允许纯数据清单和人设正文，自动检查文件与哈希，不执行代码；Api 1/2 工具继续做静态包检查。
- Api 3 每版本提供发布主体数字 ID 和固定源码 commit，包放市场固定版本路径，旧包不可覆盖。市场使用固定宿主运行时在 GitHub 托管虚拟机模拟执行，错误回退、超时及越权均判失败。
- 检测报告绑定 ZIP 哈希与版本；正式默认分支通过后由独立任务签署。首次门禁启用、报告查询及能力边界见随包「插件安全检测.md」和市场仓库 `security/README.md`。

## 1. 操作入口

- 插件必须在「插件市场 → 已安装」管理。卡片提供启用、停用、卸载和设置。
- 市场目录和插件 ZIP 支持内置公钥验签（ECDSA P-256）：**有签名就必须验过，没有签名按未签名加载**，仍校验下载域名白名单、SHA-256 和包内清单一致。哈希只用于发现传输损坏，不能替代签名。私钥与签名流程见 `docs/插件市场签名.md`。
- 插件工具的配置、预览、执行、权限确认和结果统一放在「插件市场 → 已安装」的插件卡片「设置」里。用户从设置返回市场后，可以继续管理其他插件。
- 插件不得自行往左侧工作台、状态页、系统设置页或托盘添加入口。宿主已有页面可以展示插件提供的内容，例如宿主人设页可展示、预览和应用已启用的人设预设。
- Api 1/2 的启用只登记插件可用，需要操作时由用户在相应操作入口按次确认。Api 3 消息插件启用时确认持续参与消息处理，授权持续到停用。安装和更新都不能视作授权。

## 2. 功能扩展

- 插件可以实现自己的业务逻辑。要影响鲸鲸内核，由宿主提供版本化扩展点。每个扩展点必须声明输入、输出、可更改的范围、授权方式和异常回退。
- 消息接收、回复判定、提示词、生成替换、回复调整、发送前和网关提交结果已在 4.1.0提供扩展点。其他能力先说明用途和需要读写的数据，由宿主明确接口后开放。
- 市场包不得直接修改鲸鲸程序文件、替换 EXE、加载任意 DLL 或执行安装脚本。需要替换核心逻辑时，必须使用目标版本已发布且允许替换该行为的扩展点。
- 同一插件 ID 不能更换类型；市场更新必须保持作者一致，作者变化时只能先卸载旧版本再安装。卸载会删除插件包、授权、设置和该插件的全部会话状态，避免同 ID 新插件继承旧数据。
- 缺少接口时，暂停上架并说明缺少的扩展点、输入输出、所需权限和影响的功能。插件任务禁止改宿主源码、推送主仓库分支和给主仓库开 PR。只有用户另行明确授权，才把宿主接口作为独立任务处理。
- 插件故障或超时，应能停用该插件并回到宿主默认行为。涉及原有用户配置和记忆的写入，必须有可核对的变更范围和恢复路径。

## 3. 权限和数据

- 4.1.0的 Api 3 消息插件，可经持续授权自动参与消息流程并保存独立会话状态。chat.history 允许读取最近 12 条会话消息，model.prompt 允许读取和替换本轮系统提示词。启用时必须确认持续授权，更新后重新启用。具体扩展点及返回结构在市场右侧「消息插件 API」中查看。消息插件每条消息共享总执行预算，跨会话有全局进程并发上限；超限时宿主按默认行为继续，不会无限排队。
- 缺少声明或授权的能力一律拒绝。每项能力独立授权；更新增加能力时，必须重新确认。插件看不到模型密钥、微信凭据和任意本地文件。
- 网络、聊天历史、模型调用和发送由鲸鲸宿主代办。宿主必须核对目标、范围、账号和用户授权。插件直接收到的数据限于当前能力所需。
- Api 2 支持文本输入输出与手动消息汇总。在支持所需能力的正式客户端和对应市场校验上线前，兼容测试版可本地试装。消息汇总每次须由用户选择今天或昨天并确认，范围包括本机该日期内可用的群聊和私聊片段。使用云端模型时，片段会发给模型服务商，可能产生费用。插件只接收模型生成的汇总。Api 2 不提供原始消息接口。Api 3 可经 chat.history 授权读取最近 12 条消息。上述 Wasm 接口不提供定时运行、修改核心配置和跨会话主动发送；这些能力使用最低 4.1.2 的 JavaScript Api 4。
- 人设插件启用时登记预设。用户在插件卡片「设置」或宿主人设页预览并确认应用，宿主按既有人设校验保存。停用会从预设列表移除该条目，停用或卸载后，已经应用的自定义提示词仍会保留，可由用户手动编辑或应用其他预设。

## 4. 上架与更新

- 个人预设可以把 ZIP 直接分享给群友。对方用「插件市场 → 从本地安装」安装，作者和接收者都无需 GitHub 账号。本地包未经市场审核或市场签名，只安装来源可信的 ZIP；消息插件会显示扩展点和附加权限，人设包应用前先预览提示词。
- 公开上架 PR 只提交到 `Banan1cee/whale-girl-plugins:main`。提交前核对 base 仓库和分支。没有 GitHub 账号的作者可以把材料交给愿意代交的维护者或协作者。
- 作者提交源码、安装包、版本、兼容范围、所用权限及试装步骤。**上传通道先开放、条目可以先收录**：4.1 客户端正式发布前，只要目录 CI 通过、代码可审核即可合并入库，并在 PR 注明所需客户端版本；正式客户端发布后再补同一份 ZIP 的试装记录。已经发布过的能力，仍须在对应正式客户端上试装通过再合并。最低兼容版本填写实际提供所需能力的最低正式版本。
- 插件 ZIP 只允许该类型定义的文件。市场校验固定版本、SHA-256、包内清单，以及可选的目录签名和插件包签名。目录（`index*.json`）由市场仓库的 `scripts/build-index.js` 从 `plugins/` 与 `packages/` 自动生成，投稿人不需要手改。新类型使用兼容的独立目录。Api 2 工具进入 `index-v2.json`，原有 `index.json` 保留给 Api 1 工具；Api 3 消息插件使用 `index-v3.json`。
- 同一个插件 ID 保持类型一致。更新升版本号，原包保留。安装、启用、拒绝权限、错误回退、停用和卸载都要验证。
