# 鲸鲸插件市场规范

当前只有一种可执行插件协议：**whale-plugin/1**（见 [插件协议](插件协议.md)）。
人设包（纯数据）继续支持。

## 1. 哪些东西能装

| 类型 | 说明 | 现状 |
| --- | --- | --- |
| 统一协议插件 | ZIP 根目录含 `plugin.json`，以及 1–3 级的 `plugin.wasm` 或 4 级的 `plugin.js` | 支持本地安装与试装 |
| 人设包 | 纯数据 `plugin.json` + `persona.json`，不执行代码 | 支持本地安装与分享 |

远端 `Banan1cee/whale-girl-plugins` 目前只发布 `index-personas.json`；新协议目录 `index-v5.json` 的接入步骤见 [插件市场适配](插件市场适配.md)。
启动器只读取真实存在的人设目录，不会把旧目录当成新协议来源。
新协议的公开投稿要等市场仓库同步目录生成、校验与 CI 之后才开放。

## 2. 客户端版本与代次

- `minAppVersion` / `maxAppVersion` 决定能装到哪个鲸鲸版本。
- `appEpoch`（1 = 旧 4.x 体系，2 = 正式版体系）解决 4.x 与 1.x 不能直接比较数字的问题。
- 需要同时兼容两代时用 `appCompatibility`：

```json
{
  "minAppVersion": "4.3.0",
  "appCompatibility": [
    { "appEpoch": 1, "minAppVersion": "4.3.0" }
  ]
}
```

数组 1–2 项，同代不能重复；每项可选 `maxAppVersion`，且不得小于该项下限。
顶层 `minAppVersion` 仍要保留真实范围。

## 3. 授权与数据

- 安装只解包校验，不执行、不授权；保存设置也不会生成授权。
- 1–3 级使用受限 Wasm，3 级回复扩展须确认聊天访问。4 级才须确认「完整系统权限」。Node 插件**不是沙箱**：它可以读写文件、联网、启动进程；
  `calls` 只限制宿主代为执行的能力，不限制代码本身。
- 每次启用签发的授权绑定：插件 ID、安装包 SHA-256、清单与入口原始字节摘要、授权代次、
  批准的 provider 列表、已启用且用户同意的 call 列表、设置快照。
- 修改设置、更新版本、停用都会重签或撤销授权；旧代次的迟到结果被丢弃。
- 宿主暂未开放的调用（`message.submit@1`）可以声明，但不会获批，也不会执行。
- 宿主管理的调用不提供模型密钥或微信凭据，但 4 级代码仍有系统权限。需要模型或检索时，通过获授权的 `model.complete@1` / `search.query@1` 代办。

## 4. 能力与作用域

能力、模式、作用域和输入输出 schema 由宿主注册表统一维护
（`src/services/pluginProtocolRegistry.json`），启动器、运行时和作者 CLI 读的是同一份定义。
同一能力同一作用域只允许一个 `replace` 提供者；冲突在调用任何插件之前拒绝。

## 5. 操作入口

- 插件只能在「插件市场 → 已安装」里管理：启用、停用、卸载、设置、手动运行。
- 插件不得往左侧工作台、状态页、系统设置页或托盘自行加入口。
- 手动运行只有 `tool.run@1`，输入按插件 `settingsSchema` 之外的 JSON 原样传入。
- 插件总开关 `features.plugins` 默认关闭；关闭会停止受管理的 Worker 并取消未执行调用。

## 6. 免责声明与风险

- 上架、扫描、签名都不构成无毒保证或官方安全认证。
- 作者和代交者须如实说明来源、功能、权限、兼容范围和已知风险。
- 完整说明见随包「插件免责声明.md」。

## 7. 投稿（尚未开放新协议）

新协议开放投稿前，市场仓库需要先完成：目录生成（`index-v5.json`）、清单与能力校验、
ZIP 摘要核对、在固定宿主环境里的模拟执行与撤销测试。在那之前：

- 可以本地打包、安装、试装，但不能宣称「已上架」或「已通过市场校验」；
- 统一协议投稿 PR 暂不接受，避免目录里出现客户端无法验证的条目。
