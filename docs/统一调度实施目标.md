# 统一调度实施目标

本文件记录已授权目标与实施状态，不是已发布插件协议。

## 固定目标

1. 解析现有链路，列出功能边界和实际依赖。
2. 确定统一契约，先固定输入、输出、替换规则。
3. 用薄适配层接入现有实现，保持原有行为，不先重写。
4. 建立调度层和 SDK，兼容已有插件 API。
5. 用回复增强、DSH 接管、独立定时任务三类插件验收。
6. 再逐步拆分内部大模块，保持插件接口稳定。

## 状态

- 目标1：已建立 `内核链路解析与调度边界.md`；静态证据与自动测试结果分开记录，真实微信验证仍未完成。
- 目标2：开始。内部注册表支持观察、增强、按范围替换；输入输出必须校验，替换冲突在执行前拒绝，不自动重试副作用。
- 目标3：已接入 webhook 网关的内置聊天薄适配器；其他入口尚未接入。
- 目标4—6：尚未完成，不宣称现有插件可用新接口。

## 当前内部契约

`CapabilityDispatcher` 只接受可结构化克隆的数据。
`define` 注册校验器及内置实现；`register` 声明提供者ID、模式、范围谓词和执行函数，返回撤销函数。
观察不得修改共享输入；唯一替换者替代内置；增强依注册顺序处理结果。
取消会拒绝迟到结果，但不能撤销已发生副作用；执行错误直接交还调用方，不自动恢复内置。

此底座已由 createRuntime 组装并接入 Gateway；没有注册提供者时调用原 Bot.handle，不改变已发布行为。不是权限管理器、安全沙箱、计时器或完整撤权协议。
超时预算、重入防护、授权代次、诊断、旧hook适配及标准能力schema必须在正式SDK开放前完成。

## 后续验收门槛

- 先把内置聊天包装成薄适配器：无插件时同输入同结果。
- 全聊天接管必须在鲸鲸记忆、提醒、搜索等业务副作用前分流，保留身份/发送保护。
- 每项能力明确数据、授权、作用域、失败和提交边界，不把所有内部函数包装成HTTP。
- Api 1/2/3/4保持兼容；不提前移动旧hook泄露范围。
- DSH先用模拟服务验证协议边界；真实接口接入需实际协议，不虚构地址/凭据。
- 新增用户可见SDK能力进入功能版本；实施前再次核对最新版本，按规则完整构建和安装测试。
- 每阶段独立回归，不覆盖当前其他协作者未提交修改。

### 在途控制补充

提供者默认30秒、最大120秒预算；外部取消、撤销注册会中止等待并拒绝迟到结果，不自动调用内置或重试。
AbortSignal只能协作取消，不能阻止完整系统权限代码继续执行外部副作用。
聊天薄适配增加同会话串行；替换路径在调用提供者前检查发言范围，并对有msgId的消息做内存去重。
去重最多保存10000条，重启不保留，不承诺跨重启恰好一次；去重占位在执行前写入，避免超时后盲目重放。
新增超时、撤销、替换串行/重复消息测试，目前底座6项、网关4项及API4管线1项通过。
仍待：持久去重/账号域、排队上限与总预算、SDK授权绑定、可安装验收插件、SSE统一适配和正式发布版本。

### 2026-11-23：宿主能力统一到同一分发器 + 全功能 SDK

- `UnifiedCapabilityDispatcher` 增加 `defineHost` / `invokeHost`：宿主能力（`registry.calls`）与插件提供者能力（`registry.providers`）共用同一份注册表校验、授权校验和输出校验。宿主内部调用传 `plugin = null`，插件 `host.call` 传插件对象并额外校验声明与授权。
