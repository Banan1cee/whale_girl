# 插件安全检测与溯源

## 先看类型

人格预设是纯数据，进入独立的人设目录，只允许 plugin.json 和 persona.json，不执行代码。可以继续直接分享本地 ZIP。Api 1/2 工具做格式、文件与哈希检查；Api 3 消息插件每个版本还需要在 Windows 虚拟机内运行测试和核对发布来源。

程序按目录要求核对 Api 和 Kind，人设目录不能混入可执行消息插件。所有配置和使用入口仍在插件卡片的「设置」。

## Api 3 投稿怎么做

向 Banan1cee/whale-girl-plugins 的 main 提交独立插件包，目录填版本和 ZIP 的 SHA-256，并提供 provenance/<id>-<version>.json。文件记录发布者 GitHub login、数字 ID、源码仓库、完整 commit 和目录。具体模板与步骤见市场仓库 security/README.md。

检测使用固定版本、固定哈希的真实宿主运行时，覆盖模拟群私聊输入、声明的消息扩展点、输出权限、超时、状态和停用。任何宿主错误回退都算检测失败。候选源码和作者的安装、构建脚本不会执行，不接真实微信，不使用真实聊天或密钥。人格预设不做动态执行。

## 去哪里看结果

打开市场仓库 https://github.com/Banan1cee/whale-girl-plugins/actions ，找到对应 PR 或版本的 market-security 运行。摘要列出插件、检查类型、结果与包 SHA-256；附件包含 security-report.json 和实际测试的 ZIP。

报告记录发布 GitHub 账号、提交者、源码 commit、宿主版本和检测时间。正式 main 检测通过后，会在独立任务为包和报告生成 GitHub artifact attestations；PR 的预览报告不作为正式签署证明。可按市场安全指南用 GitHub CLI 核验来源，再对照包哈希与报告结果。

首次启用新门禁需先合并市场的检测流程，再将「插件安全门禁」设为市场 main 必需检查。初始开发 PR 的 security-selftest 只是新流程试跑。以 Actions 的实际结果为准，不能把功能说明当成某个版本已经通过的证明。

## 安全边界

GitHub 账号验证不是现实实名验证，哈希只绑定具体文件。模拟测试不是完整病毒扫描，也不保证覆盖延迟触发或特殊输入；签署证明说明来源和检测流程，不代表绝对安全。现有客户端安装市场包时校验 SHA-256，尚未自动验证 GitHub 签署证明或远程撤回名单。请核对来源、权限和版本，先备份再启用；本地包仍需自己确认来源。
