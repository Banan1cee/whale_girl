# 插件市场签名

4.1.0 起，启动器内置一把 ECDSA P-256 公钥，支持对**市场目录（`index*.json`）和插件 ZIP** 验签：
哈希解决“文件有没有被改”，签名解决“文件是不是市场维护者发的”。

**当前签名是可选加强项**：目录没有 `.sig`、条目没有 `Signature` 时按未签名加载，
仍然校验 SHA-256、下载域名白名单和包内清单一致性；一旦提供了签名就必须验过，签错依然拒绝。
市场仓库还没配私钥时，未签名目录属于正常状态，不会把整个市场挡在门外。

## 信任根

- 公钥在 `launcher/PluginTrust.cs`，当前指纹（SHA-256）：
  `135bd43efa206a50668291659154e74cb85779ca33cb13da61176b15736f7418`
  替换公钥后请同步更新这里的指纹。
- 私钥只在维护者离线环境，禁止提交到仓库。`.gitignore` 已忽略
  `plugin-market-private-key.pem` 和 `*.private.pem`。
- 公钥轮换时，把新公钥追加到 `DefaultPublicKeys`，用逗号或换行分隔；旧公钥至少保留一个发布周期，
  让用户能平滑更新。

## 目录签名

每个目录文件旁边放一个同名 `.sig` 文件：

```
index.json
index.json.sig
index-v2.json
index-v2.json.sig
index-v3.json
index-v3.json.sig
```

`.sig` 是目录原始字节的 ECDSA/SHA-256 签名，Base64 编码，可以带一个结尾换行。
启动器先下载目录字节，再下载 `.sig`，验签通过才解析。`index.json` 验签失败会直接拒绝市场；
`index-v2.json` / `index-v3.json` 是可选目录，缺签名或验签失败时跳过，不影响主目录。

## 插件包签名

目录条目的 `Signature` 字段是 ZIP 原始字节的 Base64 签名：

```json
{
  "Id": "line-counter",
  "Version": "1.0.0",
  "Download": "https://github.com/.../line-counter-1.0.0.zip",
  "Sha256": "……",
  "Signature": "MEUCIQ……"
}
```

启动器安装时会同时检查：

1. `Signature` 对下载字节验签；
2. `Sha256` 与下载字节一致；
3. 包内 `plugin.json` 与目录条目除下载地址、哈希、讨论编号和签名外完全一致。

本地 ZIP 没有市场签名，仍可安装，但确认框会明确标注“未经市场审核或签名”。

## 维护者操作

准备私钥（只生成一次，离线保存）：

```powershell
node -e "const {generateKeyPairSync}=require('crypto');const {publicKey,privateKey}=generateKeyPairSync('ec',{namedCurve:'P-256'});require('fs').writeFileSync('plugin-market-public-key.txt',publicKey.export({type:'spki',format:'der'}).toString('base64'));require('fs').writeFileSync('plugin-market-private-key.pem',privateKey.export({type:'pkcs8',format:'pem'}))"
```

把公钥内容替换到 `launcher/PluginTrust.cs` 的 `DefaultPublicKeys`，私钥留在离线机器。
替换后同步更新 `docs/插件市场签名.md` 的指纹，以及 `tests/plugin-market/Program.cs` 里用旧私钥生成的
`node-signed payload` 测试签名，否则回归会明确失败。

给插件包签名：

```powershell
node scripts/plugin-market-sign.js package dist/line-counter-1.0.0.zip --key plugin-market-private-key.pem
```

把输出的 Base64 填进目录条目的 `Signature`。然后签目录：

```powershell
node scripts/plugin-market-sign.js catalog index.json --key plugin-market-private-key.pem
node scripts/plugin-market-sign.js catalog index-v2.json --key plugin-market-private-key.pem
node scripts/plugin-market-sign.js catalog index-v3.json --key plugin-market-private-key.pem
```

最后用公钥复核：

```powershell
node scripts/plugin-market-sign.js verify index.json --signature-file index.json.sig --public-key plugin-market-public-key.txt
```

## 发布顺序

1. 有私钥时，先用同一把私钥给目录和要上架的 ZIP 签名；
2. 再合并市场目录；
3. 目录和包都带签名后，客户端自动走验签；未签名时只跳过签名这一步。

签名是加强项而不是前置条件：市场仓库还没配私钥时，未签名目录照常可用，主依据仍是
“市场仓库的固定版本 + SHA-256 + 下载域名白名单 + 包内清单一致”。等私钥就位再逐步补齐签名，
不需要为了等签名把市场整个关掉。
