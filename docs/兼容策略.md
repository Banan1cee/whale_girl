# 兼容策略（断代迁移版）

> 目标：把「为了老版本而一直留在主流程里的代码」收敛成一次性迁移 + 明确契约；不盲目删除仍被当前微信/旧数据/已发布插件使用的分支。

## 1. 判定标准

一条兼容代码只有在满足下面任一条件时才保留：

1. **当前微信运行时仍会走到**：例如 4.1 的 GBK 与 4.2 的 UTF-16、托盘恢复、SPI/gate 物化。
2. **已发布的对外契约**：`/api/*`、`/webhook/*` 文档字段、API3/API4 插件、更新清单旧字段。
3. **用户数据迁移**：只有在有旧 `data/` 的机器上才需要；应移到一次性迁移工具，而不是每次启动都跑。

不满足的（启动横幅、未用常量/导出、重复工具壳）直接删除。

## 2. 保留清单（不能按「旧」删）

- **微信 4.1 / 4.2 发送编码**：`bg_sender.py` 的 GBK/UTF-16 双路径、`sniff_char_mode`、`charMode=auto`；当前机器实测微信 4.2 语义走 UTF-16，4.1 老库仍可能走 GBK。
- **UIA / SPI / gate 物化**：`uia_boot.py`、`bg_sender.py` 的屏幕阅读器与候选 RVA；当前微信窗口隐藏时必须靠它。
- **uia_compat / window_activation / moment_compat / media_key_compat**：按进程找窗、托盘、双开、朋友圈补丁。
- **API3（Wasm）与 API4（JS）**：已发布插件协议；删 API3 会打断市场插件。
- **`/api/*` 与 `/webhook/*` 文档字段**：启动器/桥接唯一通道；`/healthz` 的 `service='whale-girl'` 也是契约。
- **settings.json 阴影清理、字符串布尔、按群名禁言**：老用户配置仍可能触发；先做一次性清库/写回，再删读取分支。
- **更新清单 `force` / `force_from`**：历史客户端仍在解析；等最低支持版本高于 4.1.6 再删。
- **旧图片 Key 位置、旧 `runtime/ffmpeg/bin`**：升级用户仍可能依赖；迁移后再删。

## 3. 断代迁移（建议 v5 起）

### 3.1 配置

- 只写 `data/config.json`；根 `config.json`、`data/settings.json` 只在迁移工具中读取。
- 迁移工具：读取旧文件 → 校验 → 写 `data/config.json` → 备份旧文件到 `data/legacy/` → 输出报告；失败不删除旧文件。
- 迁移完成后，启动流程不再读根 `config.json`/旧 settings 阴影；旧值缺失时用默认值并明确提示。

### 3.2 记忆

- 只写记忆 v2（`data/memory/chats/<hash>/`）。
- `data/store.json`、`data/memory.json`、`.journal` 只由 `scripts/memory-tool.js import` 手动迁移；启动时不再自动跑 `migrate.js`。
- 旧 v1 备份只支持手动 `restore --legacy`，不进入日常恢复路径。

### 3.3 人设

- 保留 `data/persona.json` 的新字段；旧 `preset/text/emotions` 由迁移工具一次性转成 `customPrompt`。
- 移除 `newBehavior=false` 旧行为分支前，先在启动器隐藏开关并迁移 `sourcePreset`；旧行为只保留一个只读兼容包。
- 旧角色预设已从仓库删除，不再随包分发；需要旧版行为时从历史 tag 取回对应 JSON 再手动导入。

### 3.4 插件

- API3/API4 都保留；只清理未文档化的测试导出/旧执行顺序兼容代码。
- 插件设置/授权迁移到当前 `*.flow-grant.json`；旧 `*.flow.json` 只在迁移工具里读。

### 3.5 更新/安装

- 继续解析旧 `force`/`force_from`；新清单优先 `force_versions`。
- 安装包继续使用 WPF 单文件启动器（`launcher/publish/WhaleLauncher.exe`，需 .NET 10 Desktop，安装器负责检测/安装）；评估过的 WinUI 3 自包含目录方案已放弃。
- 根目录 `WhaleLauncher.exe` 与 `launcher/` 源码保持同步，安装包与快捷方式都以它作为唯一入口。

## 4. 执行顺序

1. 删除确认死代码（启动横幅、未用常量/导出、重复工具壳）。
2. 增加一次性迁移命令与报告；把启动自动迁移改为「检测到旧数据时提示 + 手动执行」。
3. 删除启动路径里的旧配置/旧记忆/旧人设分支，保留迁移命令。
4. 清理未文档化的 webhook 别名字段（先发弃用说明）。
5. 更新文档与测试：`docs/设置说明.md`、`docs/迁移说明.md`、`tests/config-*`、`tests/memory-migration*`。

## 5. 禁止事项

- 不因为「代码老」删除微信 4.1/4.2 运行时分支。
- 不删除 `/api/*`、`/webhook/*` 文档字段、API3/4。
- 不在没有备份/报告的情况下删除旧 `data/`。
- 不把迁移逻辑继续塞进每次启动的热路径。
