# 公告与通知

4.2.0 起启动器支持「公告」：远端一份只读 JSON，启动时弹窗提醒，顶栏铃铛看历史。公告不随版本发布，改文案不需要发安装包；但它也**只负责告诉你**，不是强制更新，不能停用版本，永远不会影响启动。

数据文件在公开仓库的 `website/content/announcements.json`。官网构建脚本（`scripts/build-website.js`）会把整个 `website/` 目录复制进产物，所以同一个文件同时挂在 GitHub raw 和官网静态站上。

## 数据源与仲裁

客户端并行拉这四个源（单源 4 秒超时），按 `manifest_version` 取序号最大的那一份：

| 源 | 地址 | 生效时间 |
| --- | --- | --- |
| GitHub raw（主源） | `https://raw.githubusercontent.com/Banan1cee/whale_girl/main/website/content/announcements.json` | 合并 main 后秒级 |
| 官网静态站 | `https://bot.zyyc.cc/content/announcements.json` | 官网构建，1～3 分钟 |
| gh-proxy 镜像 | `https://gh-proxy.com/https://raw.githubusercontent.com/Banan1cee/whale_girl/main/website/content/announcements.json` | 跟随 raw |
| jsDelivr CDN | `https://cdn.jsdelivr.net/gh/Banan1cee/whale_girl@main/website/content/announcements.json` | CDN 缓存，见下 |
| GitHub Release 资产 | `https://github.com/Banan1cee/whale_girl/releases/latest/download/announcements.json` | 上传到「最新已发布 Release」后立即可读；没挂资产就是 404，不影响其它源 |

- 四份都拿不到、或者都不是合法 JSON：用本地缓存（最近一次成功拉到的原文）；连缓存都没有就当没有公告，完全静默。
- 在线响应的 `manifest_version` **低于**本地缓存时，不覆盖缓存（jsDelivr 对 `@main` 有缓存，可能吐出旧份）。这条和更新清单是同一套序号仲裁规则。
- 公告读取失败、写状态失败都只记一条内部告警，启动流程照常往下走。

## 顶层字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `schema` | 整数 | 必须是 `1`；将来结构不兼容才升 |
| `manifest_version` | 正整数 | 每次修改严格递增，**回滚也要递增**；客户端靠它在多源之间取最大份 |
| `updated_at` | ISO8601 字符串 | 本次修改时间，UTC，例如 `2026-11-24T12:00:00Z` |
| `kill` | 布尔 | `true` = 全部公告撤下，连历史面板也不显示；默认 `false` |
| `config` | 对象 | 展示节奏，见下一节；缺字段按默认值 |
| `announcements` | 数组 | 公告条目；可以为空数组 |

## config（远端可调，客户端本地钳制）

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `popups_enabled` | `true` | 远端总开关；`false` 时仍然拉取、铃铛照常，只是不弹窗 |
| `max_popups_per_launch` | `3` | 一次启动最多弹几条；**客户端本地钳制 0～20**，远端写 999 也只弹 20，写负数按 0 |
| `popup_delay_ms` | `1200` | 更新检查完成后等待多久再弹第一条；客户端本地钳制 0～10000 |

远端只能把节奏调慢或调在安全范围内，不能靠 config 突破客户端上限。

## 公告条目字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 正则 `^[a-z0-9][a-z0-9._-]{0,63}$`，全文件唯一；**同一个 id 在本机一辈子只弹一次**，换内容不换 id 不会对已读用户重弹 |
| `title` | 是 | 清洗后 ≤60 字符（实际建议 ≤30 个汉字，太长弹窗会挤） |
| `body` | 是 | ≤400 字符，允许 `\n`；纯文本，不渲染 HTML |
| `level` | 否 | `info`（默认）/ `warn` / `critical`；`critical` 弹窗按警告色显示 |
| `action` | 否 | `none`（默认）/ `open_url` / `check_update` |
| `url` | 仅 `open_url` | 必须 `https`、无 userinfo、端口 443，host 属于 `github.com` / `raw.githubusercontent.com` / `bot.zyyc.cc` / `afdian.com`（含其子域）；不合格就退化成纯文本 |
| `published_at` | 否 | ISO8601；仅用于排序和历史展示 |
| `min_version` | 否 | 2～4 段数字版本号（可带 `v` 前缀），按数值比较；本机低于它就不显示 |
| `max_version` | 否 | 同上；本机高于它就不显示 |
| `epoch` | 否 | 整数且 >0；本机代次 >0 时要求相等，跨代公告不会串台 |
| `priority` | 否 | 整数，默认 0，越大越先弹；客户端内部再钳到 -1000～1000 |

容错规则：

- 单条字段写错只跳过这一条，不影响同一份里的其他公告。
- 整份 JSON 解析失败、顶层不是对象、`announcements` 不是数组：按「没有公告」处理。
- 展示前统一清洗：控制字符、双向文本标记会被去掉，`title` 截到 60 字符、`body` 截到 400 字符。

## 展示规则

1. **时机**：启动器启动、**更新检查完成之后**才弹公告。若更新策略判成 Force / Kill 且正在走更新流程，本次不弹，留到下次启动。
2. **条数**：一次启动最多弹 `max_popups_per_launch` 条（客户端本地钳制 0～20）。按 `priority` 降序、`published_at` 降序取前 N 条。
3. **弹窗**：每条公告一个弹窗，纯文本；「知道了」关闭。`action=open_url` 的按钮是「打开链接」，`action=check_update` 的按钮是「检查更新」。
4. **只弹一次**：每条 `id` 在本机一辈子只弹一次，弹过立刻记已读并写状态文件。
5. **跳过本批**：本批不止一条、且这条带有动作按钮时，弹窗会多一个「跳过本批」；点了就把本批还没弹的 `id` 一起记已读，本次启动不再弹。
6. **运行中刷新**：启动器一直开着时，每 6 小时静默拉一次，**只更新缓存和铃铛未读数，不弹窗**、不打断正在做的事。
7. **顶栏铃铛**：有未读时显示红色数字，未读数 >9 显示 `9+`。点开是「公告」面板，按优先级和发布时间列出全部公告（含已读），未读带圆点；打开面板即清空未读（全部记已读）。
8. **`kill: true`**：公告全部撤下，连历史面板里也不显示。
9. **`popups_enabled: false`**：不弹窗，但公告照常拉取、铃铛照常提示。

## 状态文件

`%LocalAppData%\WhaleGirl\announcements-state.json`

```json
{
  "read": {
    "2026-11-example-notice": "2026-11-24T12:03:00.0000000+00:00"
  },
  "cache": {
    "schema": 1,
    "manifest_version": 7,
    "updated_at": "2026-11-24T12:00:00Z",
    "kill": false,
    "config": { "popups_enabled": true, "max_popups_per_launch": 3, "popup_delay_ms": 1200 },
    "announcements": []
  },
  "cached_at": "2026-11-24T12:03:00.0000000+00:00"
}
```

- `read`：已读（弹过或点开过面板）的 `id` → 时间；只保留最近 500 条，防止状态文件无限增长。
- `cache`：最近一次成功拉取的完整 feed 原文，断网时回退用。
- `cached_at`：缓存时间。
- 写入走临时文件 + 原子替换；文件损坏按「没用过」处理，下次成功拉取重写。手动删掉这个文件等于清空已读，已弹过的公告会再弹一次。

## 发布流程

1. 只改 `website/content/announcements.json`，一般不需要发版。
2. 新公告用新的唯一 `id`（小写字母/数字/`.`/`_`/`-`，建议带日期，例如 `2026-11-example-notice`），按上一节字段写。
3. 把 `manifest_version` 严格 +1（每次修改都加，回滚内容也要加，**不能退回小序号**，否则 jsDelivr 和本地缓存会继续压住新内容），`updated_at` 改成当前 UTC 时间。
4. 提 PR，CI 通过后合并 main。不要直接 push main。
5. 生效时间：GitHub raw 合并后秒级；官网 Pages 构建 1～3 分钟；客户端**下次启动**才弹；运行中的客户端最多 6 小时后铃铛出现未读。
6. 紧急撤下：把 `kill` 改成 `true`（连历史一起隐藏），或删掉对应条目，并同时把 `manifest_version` +1 提交。恢复时 `kill: false` 同样要 +1。已经装了旧缓存且断网的客户端要等下一次联网拉取才撤干净。
7. 用 GitHub Release 资产做测试：把文件命名为 `announcements.json` 上传到**最新已发布**的 Release（草稿、预发布不算 latest），客户端会并行读到它；同样按 `manifest_version` 取最高那份，所以测试文件的序号要高于 `website/content/announcements.json`。测完记得删掉这个资产，否则它长期按更高的序号压住正式内容。
8. 本地自查：`node tests/announcements.test.js`（校验 JSON 字段、源码门禁和本文档关键字）。

## 本地发公告工具（不参与 EXE）

`scripts/announce.js` 只改 `website/content/announcements.json`，由 Node 直接跑，**不参与启动器编译，不会被编进 `WhaleLauncher.exe`**。

```bash
# 追加一条（自动递增 manifest_version、刷新 updated_at）
node scripts/announce.js "官网域名已更新" "官网正式域名为 bot.zyyc.cc"

# 带等级 / 链接 / 按钮
node scripts/announce.js "微信 4.2 发送修复" "建议更新到 4.2.0。" --level warn --action open_url --url https://github.com/Banan1cee/whale_girl/releases

# 只提醒一次、只给 4.2.0 及以上
node scripts/announce.js "新版本提醒" "正文" --min-version 4.2.0 --priority 20

# 改节奏（写入 config，客户端仍会本地钳制）
node scripts/announce.js "调试" "正文" --max-popups 5 --delay 800

# 查看 / 删除 / 撤下
node scripts/announce.js --list
node scripts/announce.js --remove <id>
node scripts/announce.js --kill
node scripts/announce.js --unkill

# 提交并推当前分支（不会直接推 main），打印 PR 链接
node scripts/announce.js "标题" "正文" --push
```

写盘前按和客户端同一套规则校验；写完还会自动跑 `tests/announcements.test.js`，不通过就回滚原文件。`--dry-run` 只看结果不写盘。

## 本地预览（让启动器读到这份文件）

启动器默认读远端四个源，**不会读你本地仓库里的文件**。想在发布前先看效果，有两种办法：

**A. 本机覆盖（推荐，改完立刻生效）**

把要发的 `announcements.json` 放到安装目录：

- `data\announcements.json`（优先，升级不丢）
- 或安装目录根 `announcements.json`

启动器启动时优先读它、跳过远端和缓存，只影响本机；删掉文件就恢复读远端。状态行会显示「公告读自本机 announcements.json（仅本机可见）」，避免误以为已经发布给所有人。

**B. 写进本机缓存（不落文件、适合临时试）**

```bash
node scripts/announce.js --seed-local examples/announcements-sample.json
```

它把示例的序号抬到 1000000 写进 `%LocalAppData%\WhaleGirl\announcements-state.json`，启动 `WhaleLauncher.exe`（会弹 UAC）就能看到弹窗和铃铛。测试完执行：

```bash
node scripts/announce.js --clear-local
```

这份缓存只影响本机；别的机器和真实用户读到的还是远端文件。示例文件在 `examples/announcements-sample.json`，也可以直接拷进 `website/content/announcements.json`，记得把序号 +1。


## 完整示例

```json
{
  "schema": 1,
  "manifest_version": 7,
  "updated_at": "2026-11-24T12:00:00Z",
  "kill": false,
  "config": {
    "popups_enabled": true,
    "max_popups_per_launch": 3,
    "popup_delay_ms": 1200
  },
  "announcements": [
    {
      "id": "2026-11-example-notice",
      "title": "示例公告：启动器公告已上线",
      "body": "这是一条示例公告，用于演示发布流程。\n公告只做提醒，不会影响启动。",
      "level": "info",
      "action": "open_url",
      "url": "https://github.com/Banan1cee/whale_girl/releases",
      "published_at": "2026-11-24T10:00:00Z",
      "min_version": "4.2.0",
      "priority": 10
    }
  ]
}
```

## 安全与边界（不能吹）

- **没有签名验签**：公告 JSON 目前没有签名。客户端做的是「多源 + `manifest_version` 仲裁 + 只认官方仓库路径」，这只防旧缓存和单点故障，**不等于验证发布者身份**；能改 main 的人就能发公告。不要对外声称「已验证发布者」。
- **只有新版本看得到**：只有装了带本功能版本（4.2.0 起）的客户端才会读公告；旧版本没有这段代码，永远看不到。所以公告功能本身需要一次发版作为「能力上线」，之后公告才是纯远端更新。
- **不能强制更新、不能停用版本**：公告只负责「告诉你」。要拦版本请改 `release-manifest.json` 的 `force_versions` / `kill_below`，见 [强制更新与熔断](强制更新与熔断.md)。
- **永不影响启动**：下载失败、超时、解析失败、状态文件写失败，都只是少一次提示，启动照常。
- **链接只开白名单**：只允许 `https`、无 userinfo、443 端口，host 属于 `github.com` / `raw.githubusercontent.com` / `bot.zyyc.cc` / `afdian.com`（含其子域）；其他链接直接退化成纯文本，不会打开浏览器。
- **不渲染 HTML**：`body` 是纯文本，保留换行，其余控制字符清掉；不支持链接跳转以外的交互。
- **内容是公开的**：公告文件在被公开的 `website/` 目录里，官网也整目录发布。别写用户隐私、内部地址、密钥或未公开的漏洞细节。
- **离线缓存会滞后**：断网客户端只能看到上次缓存，撤下/修改要等它下一次成功联网拉取。

## 常见坑

- 改了内容忘加 `manifest_version`：jsDelivr / 本地缓存继续用旧份，用户看不到。
- 回滚把序号改小：客户端判定在线响应更旧，继续用本地更新过的缓存。
- 想复用旧 `id` 再弹一次：同一个 `id` 一辈子只弹一次，已读用户不会再弹（面板里还能看到）。要重弹请用新 `id`。
- `url` 不满足白名单：不报错，只是 `action` 退化成 `none`、链接不显示。
- `action` 拼错（例如 `open-url`）：按 `none` 处理。
- `title` / `body` 超长：截断，不是报错；但弹窗体验会变差。
- 想用公告通知旧版本升级：旧版本读不到公告，只能用 `release-manifest.json`。
- 把 `max_popups_per_launch` 调很大：本地最多 20 条，而且还要过「已读」过滤。
- 以为公告是实时推送：客户端只在启动和每 6 小时周期拉取时更新，别指望秒级触达所有在线用户。
