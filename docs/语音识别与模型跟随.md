# 看图、语音识别与搜索的模型配置

新安装默认沿用「设置 → API 接入 → 聊天」中保存的服务商、接口和 Key。跟随不是锁定：各页签可以选择手动配置，切换聊天模型不会覆盖这些手动设置。升级时已有的关闭状态和手动配置继续保留。

## 看图

- 自动模式下，聊天模型支持图片时使用同一个模型。
- 已知聊天模型不支持图片时，界面提示原因，并显示自动选用的同服务商视觉模型。例如 DeepSeek V4 Pro 使用 DeepSeek Flash 看图。
- 尚未确认的模型不显示为“已确认支持”，请使用看图测试或手动选择已支持图片输入的模型。
- 选择手动服务后可独立修改接口、模型和 Key。自动模式只使用当前聊天 Key，清空聊天 Key 不会借用旧的专用 Key。

## 语音识别

这是接收微信语音后转文字，与工作台的「语音发送」独立。

- 「语音服务 → 跟随主模型」复用聊天服务和 Key，实际转写使用专用语音接口，而非把音频交给任意文本聊天模型。
- 已适配 DeepSeek 官方 ASR 和千问官方 `qwen3-asr-flash`，百炼沿用所选地域。第三方中转、自建和其他服务不会自动借 Key 发往另一家官方接口，界面会提示尚未适配。
- 可手动选择 DeepSeek、百炼或自定义接口并填写独立 Key、模型与地址。自定义目前使用百炼兼容 JSON 格式，并不代表兼容所有 ASR 协议。
- 收到每条语音时读取当前聊天设置，更换聊天 Key 后无需重启桥接。刚修改语音总开关等主配置时，等待现有配置热更新完成（约 5 秒）。
- 关闭总开关后不下载语音、不请求识别，专用语音 Key 按原有关闭流程清除；聊天 Key 保留。
- 「测试语音识别」上传用户自行选择的 WAV，需在确认后调用服务商；识别可能产生音频用量费用。

程序需要先将微信缓存的 SILK 语音解码为 WAV。打包依赖为 `silk-python==0.2.9`；修复旧运行包时先复制到暂存目录，再执行 `scripts/prepare-voice-runtime.py` 安装指定官方 wheel 并进行离线编码/解码验证。不要手动修改第三方源码，也不要用用户聊天语音做构建测试。

## 搜索

聊天使用 DeepSeek 官方 `deepseek-flash` 时，使用模型内建搜索并复用聊天 Key，不会自动调用下方独立搜索。切换到不支持内建搜索的聊天配置后，仍可使用已保存的独立搜索设置。插件显式调用搜索与聊天的自动联网独立。

- 「启用搜索 API」是独立搜索 API 的总开关；「跟随主模型」可以独立关闭。
- 跟随时 DeepSeek 使用官方搜索接口，千问使用当前聊天模型的官方联网搜索接口，共用聊天 Key；只采信接口返回的来源列表，不把模型自由生成的链接当证据。
- 暂未适配的服务继续使用聊天模型判定是否联网，再由本地 Bing/360 获取结果。API 超时、失败或无结果时保留本地搜索兜底。
- 关闭跟随后可按原界面手动添加 DeepSeek / 知乎搜索并填写独立凭据；关闭总开关后只使用本地搜索。关闭搜索 API 不会删除聊天 Key。
- 共用 Key 不等于免费；是否可用、额度、权限与计费以服务商为准。

接口依据：[DeepSeek ASR](https://api-docs.deepseek.com/guides/asr/)、[千问 ASR](https://help.aliyun.com/zh/model-studio/qwen-asr-api-reference)、[千问联网搜索](https://help.aliyun.com/zh/model-studio/web-search)。
