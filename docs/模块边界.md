# Node 内核模块边界（多 agent 协作约定）

> 目标：按业务能力拥有代码，模块之间只通过公开入口和注入交互；让多个 agent 能各写各的目录，不抢同一个文件。
> 本轮只重组 Node 内核；`bridge/`、`launcher/`、`tests/` 目录布局保持不变。

## 目标结构

```text
server.js                    # 固定入口（安装器/旧快捷方式依赖）
src/
  app.js                     # 组合根：唯一的实例装配点（集成人维护）
  bootstrap/
    modules.js               # 只发现 src/modules/*/manifest.js
  modules/<domain>/
    index.js                 # 对外公开 API：跨模块唯一允许的 require 目标
    manifest.js              # id / order / create / routes；加载时不创建实例
    service.js               # 模块私有实现
    routes.js                # 模块私有 HTTP 注册
  core/ pipeline/ persona/ memory/ llm/ adapters/   # 共享能力（按 pass 逐步迁移）
  infra/                     # 配置、日志、调度、文件与路径
  http/                      # Router、协议工具、全局请求安全检查
  services/                  # 共享用例平台层（status/settings/debug/apiProbe/envInfo/configCommands…）+ 旧启动器 CLI 入口（永久）
```

模块目录按需保留 `pipeline/`、`store/`、`providers/` 等子目录；不要为了对称强行拆。

> `src/persona/`、`src/memory/`、`src/pipeline/` 目前保留为**平台库**：目录本身已按领域隔离，但被 `infra/configPatch`、`textBudget`、`Bot` 等底层单源依赖牵动。Pass 4 完成的是 HTTP 路由模块化；这些库的物理迁移/注入/常量下沉是后续独立任务，不在本轮范围。

## 模块责任

| 模块 | 拥有的职责 |
| --- | --- |
| `wechat` | Node 侧网关、账号、联系人、桥接心跳、`/webhook/*`、发送许可 |
| `chat` | `/api/chat`、`Bot`、消息判定与回复管线、对话预算展示 |
| `persona` | 人设预设、导入导出、提示词、人设存储、风格画像 |
| `memory` | 会话、检索、摘要、人物卡、token 分配、备份恢复、`/api/memory/*` |
| `stickers` | 图库、预设导入、选图、发送任务与回执 |
| `moments` | 朋友圈缓存、读取调度、点赞、发表任务与账号确认 |
| `reminders` / `care` | 提醒解析/持久化/领取/回执；主动搭话目标/时间窗/文案 |
| `diary` / `digest` | 每日日记生成与投递；按请求生成消息汇总 |
| `plugins` | Wasm/JavaScript 插件宿主、worker、授权与生命周期 |
| `settings` | `/api/config`、`/api/settings`、功能开关、状态与诊断聚合 |
| `voice` / `vision` / `search` | Node 侧语音意图与识别探测；图片理解与 API；搜索与网页读取 |

## 硬规则

1. **跨模块静态依赖只走公开入口**：`require('../other')` 解析到 `modules/other/index.js`；禁止 `modules/other/service` 等深 import。
2. **实例依赖用注入**：模块导出 `create(runtime, deps)`；不要在模块里 require 另一个模块的单例。`runtime` 现有字段保留兼容。
3. **`services/` 是共享用例平台层**：模块可以 require `../../services/*`（status/settings/debug/apiProbe/envInfo/configCommands 等）；但跨模块仍只走公开 `index.js`，不得深 import 别的模块。
4. **清单只声明，不执行**：`manifest.js` 不创建实例、不启动定时器；`bootstrap/modules.js` 只扫描并校验。
5. **路由顺序必须保留**：每个注册项带 `order`，按原顺序注册。Router 对精确/正则路由各取首个匹配，插件 `apiRoutes` 也按注册顺序生成；不能按目录名排序。
6. **一个集成人**：`src/app.js`、`src/http/routes/index.js`、`src/bootstrap/`、`scripts/check-layers.js`、`CHANGELOG` 只由集成人合并修改。
7. **平台层不得反向依赖模块**：`core` / `pipeline` / `persona` / `memory` / `llm` / `adapters` / `infra` 不得 require `modules` 或 `bootstrap`。
8. **旧启动器 CLI 永久保留**：`src/services/launcherSnapshot.js`、`src/services/stickerLibraryLocal.js` 必须保持可执行、stdin/stdout/退出码不变；不能只放 `module.exports` 转发。
9. **过渡例外要写明到期**：目前只允许 `pipeline -> modules/search`（旧聊天管线仍直接消费搜索），Pass 4 把 pipeline 并入 chat 模块后删除；不得借此新增 `pipeline -> modules/stickers|reminders|voice`。
10. **兼容层转发同一实现**：迁移期旧路径 shim 必须转发同一个 `module.exports`，不复制导出、不重复构造；每个 pass 结束清理无调用方的临时 shim。
11. **测试平铺**：普通测试继续放 `tests/*.test.js`，自动进入 CI；只有新增/变更 CI 任务才改 `scripts/test-tasks.json`。

> **检查范围与已知间接耦合**：`check-layers` 只静态检查直接 `require`。`services/` 作为共享用例层可以消费模块公开入口，因此存在条件性间接边，例如 `infra/configPatch`（热重载）→ `services/location`（IP 回退）→ `modules/search`。平台层仍禁止**直接** require `modules`/`bootstrap`；这类间接耦合记录在案，收口 chat 管线时一并评估。

## 多 agent 写入范围

| 角色 | 可写范围 |
| --- | --- |
| 模块 agent | `src/modules/<id>/`、该模块对应 `tests/*.test.js`、自己的说明文档 |
| 集成人 | `src/app.js`、`src/http/routes/index.js`、`src/bootstrap/`、`scripts/check-layers.js`、`CHANGELOG.md`、安装/部署/发布脚本；**统一分配新/改全局路由 order** |
| 平台用例 agent | `src/services/` 共享用例层；独立写入者，不与模块迁移并发 |
| 平台 agent | `src/core/`、`src/infra/`、`src/http/` 等共享层；单独 lane，不与模块迁移并发 |
| 桥接/启动器 agent | `bridge/`、`launcher/`；按各自契约单独排期 |

```powershell
node scripts/test-tasks.js --check
node scripts/release-check.js
node scripts/privacy-scan.js .
```
