# 鲸鲸插件作者入门

## 先判断能不能做成插件

鲸鲸 4.1 第一版插件适合做 **用户输入文字，点一下按钮，得到一个整数结果** 的工具。比如字节数、行数、某个词出现几次。工具启用后，在「插件市场 → 已安装」里点「设置」使用。也可制作人设包，启用后在「设置」预览和应用，也会出现在人格预设列表。

自动群聊日报、联网查天气、自动发微信、改主界面、改记忆逻辑，都需要鲸鲸先开放对应的接口。遇到这类需求，先提「需要什么接口」，等接口做好再做插件。修复鲸鲸本身的错误则走主仓库 PR。

如果已经让 DSH 改了一堆鲸鲸文件，先保留原改动。另开一个目录，请 DSH 把其中能独立运行的计算逻辑提取出来。最终投稿的是独立插件源码和安装 ZIP，原来的改动可以另行讨论。

## 第一步 · 把需求交给 DSH

把下面这段发给 DSH，把方括号里的内容改成你自己的。

```text
帮我把「[功能，例如数一段文字里有几行]」做成一个鲸鲸 4.1 插件。
以 Banan1cee/whale-girl-plugins 里的 examples 为模板。请在独立目录完成。
先说明当前插件接口能否实现。如果需要读微信、联网、定时或发消息，停下来告诉我缺哪项接口。
如果可以实现，请交付插件源码、可安装 ZIP、SHA-256 和至少两组输入与预期结果。
工具 ZIP 根目录只放 plugin.json 和 plugin.wasm。做人设包时改放 plugin.json 和 persona.json。保持我已经改过的鲸鲸文件原样。
先给我本地测试，等我确认后再帮我发布到 GitHub 和准备市场投稿。
```

给 DSH 的技术要求

- 清单照样板填 `Id`、`Name`、`Author`、`Version`、`MinAppVersion`、`Description`、`ResultLabel` 和 `Api`。第一版 `Api` 为 `1`。工具 `Kind` 可填 `tool`，人设包填 `persona`。`MinAppVersion` 填最低兼容版本，有最高兼容版本时加 `MaxAppVersion`。插件 ID 用小写字母开头，只用小写字母、数字和短横线。
- 工具的 WebAssembly 导出 `run() -> i32`。可调用 `whale.input_size() -> i32` 和 `whale.input_byte(index: i32) -> i32`。输入是 UTF-8，越界读取返回 `-1`。鲸鲸用 `ResultLabel` 加整数显示结果。
- 人设包的 persona.json 写成 `{"customPrompt":"你的人设正文"}`，不需要 Wasm。启用后只加入预设列表，由用户预览并选择应用。
- ZIP 最大 1 MiB，其中 `plugin.wasm` 最大 512 KiB。提交包只收插件自己的文件。真实会话、配置、记忆和密钥留在本机。

## 第二步 · 自己点一遍

1. 打开带插件市场的鲸鲸 4.1，进入「插件市场 → 从本地安装」，选择 ZIP。
2. 在「已安装」点「启用」。工具点同一张卡片上的「设置」。人设包也点「设置」，启动内核后可预览和应用。
3. 试一次正常输入和一次空输入。中文工具也试一段中文，确认结果符合预期。
4. 试「停用」和「卸载」。给别人装前，把怎么用、预期看到什么写成两三句话。

## 第三步 · 把插件交给市场审核

1. 在你自己的 GitHub 账号下建一个公开插件仓库，放源码和使用说明。可以让 DSH 准备文件，你确认以后再发布。
2. 在这个仓库的 Releases 发布 `v1.0.0`，上传刚刚试过的 ZIP。复制这个具体版本的下载链接和 SHA-256。
3. 到 [鲸鲸插件市场仓库](https://github.com/Banan1cee/whale-girl-plugins) 提交上架申请。会用 GitHub PR 的作者，可以 fork 市场仓库、在自己的分支修改 `index.json`，再开 PR。第一次不会开 PR，可以先用 Issue 交资料，由维护者代录目录。
4. 审核通过、市场目录合并后，其他人在鲸鲸点「刷新」就能看到。以后更新时沿用同一个 ID，升版本号，再发布新 ZIP 和新的 SHA-256。旧版下载包保留原样。

投稿时给维护者这几样就够了

| 资料 | 填写示例 |
| --- | --- |
| 插件名、ID、作者 | 文本行数、`line-counter`、你的 GitHub 名 |
| 版本与兼容范围 | 插件 1.0.0，鲸鲸 4.1.0 或以上 |
| 用途和使用方法 | 输入文字，点运行，显示行数 |
| 源码及安装包 | 公开源码链接、固定版本 ZIP 链接、SHA-256 |
| 试装结果 | 正常输入和空输入的预期结果，已试装的鲸鲸版本 |

## 维护者怎么审核

先核对清单、下载包的校验值和源码，再从市场待上架的同一份 ZIP 试装。确认功能、版本和用户输入的使用范围符合说明，再合并目录。每个插件可绑定一个市场仓库的 GitHub Issue，在目录里填 DiscussionIssue 编号。卡片显示评论数和爱心收藏数，用户通过 GitHub 评论或收藏。遇到问题，可以下架对应版本；作者修好后用新版本重新投稿。

软件内投稿可以后续再做。第一步可以先做「我要投稿」按钮，打开 GitHub 投稿页并引导作者准备上面的资料。等投稿量起来，再考虑在鲸鲸内接收 ZIP 和显示审核进度。

## Api 2 · 功能工具

新工具可在清单填写 `Api: 2`。WebAssembly 仍导出 `run() -> i32`，通过 `whale.output_byte(i32)` 逐字节输出 UTF-8 文本，最多 64 KiB，返回 0 表示成功。原有的输入字节接口继续可用。

需要消息汇总时，清单填写 `HostAction: chat.summary`。用户每次手动选择日期并确认。鲸鲸负责使用当前模型整理聊天内容，插件输入只收到汇总后的文字。使用云端模型时，参与汇总的聊天片段会发送给模型服务商。

Api 2 条目登记到单独的 `index-v2.json`。原有 `index.json` 供旧客户端继续使用。新的宿主能力需要鲸鲸实现并定义授权范围后才能使用。当前开放手动消息汇总，定时、读原始聊天记录、微信发送、改设置等能力需要各自独立接口。
