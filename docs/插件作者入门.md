# 鲸鲸插件作者入门

## 上架安全检测

人格预设走独立纯数据目录，只做格式、文件与哈希检查，也可继续分享本地 ZIP。Api 3 消息插件每版本须提供 `provenance/<id>-<version>.json`，声明可核验的 GitHub 发布主体和固定源码 commit，由市场自动在 Windows 虚拟机模拟运行；无需作者自己搭虚拟机。报告与安装 ZIP 哈希绑定，失败需修复后重新提交。详见软件内「安全检测与溯源」及市场仓库 `security/README.md`。

## 消息流程插件开发版

4.1.0 本地开发版新增 Api 3。消息插件可自动参与接话判定、提示词、生成替换和回复文本处理，并保存独立会话状态。清单 Kind 填 message，Hooks 声明环节，Permissions 可声明 chat.history 和 model.prompt。用户从插件卡片启用并确认持续授权，所有配置在同一张卡片的「设置」中调整。更新后需要重新启用。

目前暂未接入定时执行、跨会话主动发送和自定义语音输出。接口详情及消息 JSON 字段见随包 docs/插件消息流程Api3.md。公开上架前还需要市场接入 index-v3.json 和对应校验，当前先用本地安装验证。

## 先选分享方式

- **分享个人预设**。请 DSH 打包成人设 ZIP，自己试装后直接发群聊或私聊。对方在「插件市场 → 从本地安装」选 ZIP，启用后可在人格预设列表找到。分享和安装都无需 GitHub 账号。本地包未经市场审核，请只安装来源可信的 ZIP，并在应用前预览。分享前请清掉真实姓名、聊天记录和密钥。
- **公开上架功能插件**。准备独立插件包，向插件市场仓库投稿。没有 GitHub 账号时，可以把 ZIP、源码和说明交给愿意代交的维护者或协作者，由对方核对后代开 PR。

## 先判断能不能做成插件

鲸鲸 4.1 第一版插件适合做 **用户输入文字，点一下按钮，得到一个整数结果** 的工具。比如字节数、行数、某个词出现几次。工具启用后，在「插件市场 → 已安装」里点「设置」使用。也可制作人设包，启用后在插件卡片的「设置」或宿主人设页预览和应用。

自动群聊日报、联网查天气、自动发微信、接管记忆逻辑，都需要目标版本已经开放对应接口。缺接口时保留插件草稿，说明缺口、所需权限和受影响功能，等作者决定。修改鲸鲸宿主需要用户另行明确授权，并作为独立任务处理。

如果已经让 DSH 改了一堆鲸鲸文件，先保留原改动。另开一个目录，请 DSH 把其中能独立运行的计算逻辑提取出来。最终投稿的是独立插件源码和安装 ZIP，原来的改动可以另行讨论。

## 第一步 · 把需求交给 DSH

把下面这段发给 DSH，把方括号里的内容改成你自己的。

```text
帮我把「[功能，例如数一段文字里有几行]」做成一个鲸鲸 4.1 插件。
先读 Banan1cee/whale-girl-plugins 的 README.md 和 validate.py，以 examples 为模板，在独立目录完成。
核对目标鲸鲸版本支持的接口。仅在测试版可用的能力可以先做本地试装包。缺接口就停在插件草稿，说明缺少的接口、所需权限和受影响功能。
如果可以实现，请交付插件源码、可安装 ZIP、SHA-256 和至少两组输入与预期结果。
工具 ZIP 根目录只放 plugin.json 和 plugin.wasm。做人设包时改放 plugin.json 和 persona.json。保持我已经改过的鲸鲸文件原样。
插件的配置、授权、操作和结果统一放在插件卡片的「设置」。
先给我本地试装。人格预设直接交付可分享的 ZIP。
如果我要求公开上架，PR 只发到 Banan1cee/whale-girl-plugins 的 main，提交前核对目标仓库和分支。
未经我另行明确授权，不改鲸鲸主程序，不推主仓库分支，也不给主仓库开 PR。
```

给 DSH 的技术要求

- 清单照样板填 `Id`、`Name`、`Author`、`Version`、`MinAppVersion`、`Description`、`ResultLabel` 和 `Api`。整数工具和人设使用 `Api: 1`。Api 2 文本工具见本文最后一节。工具 `Kind` 可填 `tool`，人设包填 `persona`。`MinAppVersion` 填最低兼容版本，有最高兼容版本时加 `MaxAppVersion`。插件 ID 用小写字母开头，只用小写字母、数字和短横线。
- 工具的 WebAssembly 导出 `run() -> i32`。可调用 `whale.input_size() -> i32` 和 `whale.input_byte(index: i32) -> i32`。输入是 UTF-8，越界读取返回 `-1`。鲸鲸用 `ResultLabel` 加整数显示结果。
- 人设包的 persona.json 写成 `{"customPrompt":"你的人设正文"}`，不需要 Wasm。启用后只加入预设列表，由用户预览并选择应用。
- ZIP 最大 1 MiB，其中 `plugin.wasm` 最大 512 KiB。提交包只收插件自己的文件。真实会话、配置、记忆和密钥留在本机。

## 第二步 · 自己点一遍

1. 打开带插件市场的鲸鲸 4.1，进入「插件市场 → 从本地安装」，选择 ZIP。
2. 在「已安装」点「启用」。工具点同一张卡片上的「设置」。人设包也点「设置」，启动内核后可预览和应用。
3. 试一次正常输入和一次空输入。中文工具也试一段中文，确认结果符合预期。
4. 试「停用」和「卸载」。给别人装前，把怎么用、预期看到什么写成两三句话。

## 第三步 · 把插件交给市场审核

1. 准备试装通过的 ZIP、可审核的源码、构建说明和 SHA-256。有 GitHub 账号时，可以用自己的公开仓库和 Release 托管源码及固定版本的安装包。
2. 没有 GitHub 账号或不会操作 PR，可以把上述材料直接交给愿意代交的维护者或协作者，由对方代录目录。
3. 上架 PR 只提交到 [鲸鲸插件市场仓库](https://github.com/Banan1cee/whale-girl-plugins) 的 `main`。按仓库 `README.md` 和 `validate.py` 核对公开目录支持的类型和 API。提交前核对目标仓库和分支。
4. 审核通过、市场目录合并后，其他人在鲸鲸点「刷新」就能看到。以后更新时沿用同一个 ID，升版本号，再发布新 ZIP 和新的 SHA-256。旧版下载包保留原样。

投稿时给维护者这几样就够了

| 资料 | 填写示例 |
| --- | --- |
| 插件名、ID、作者 | 文本行数、`line-counter`、你的 GitHub 名 |
| 版本与兼容范围 | 插件 1.0.0，鲸鲸 4.1.0 或以上 |
| 用途和使用方法 | 输入文字，点运行，显示行数 |
| 源码及安装包 | 公开源码链接、固定版本 ZIP 链接、SHA-256 |
| 试装结果 | 正常输入和空输入的预期结果，已试装的鲸鲸版本 |

## 维护者怎么审核

先核对清单、下载包的校验值和源码，再从市场待上架的同一份 ZIP 试装。可以提前审核。确认提供所需能力的正式客户端已可下载，用该客户端试装通过，并且对应目录的 CI 已通过后，再合并目录。同日上线时先发客户端。每个插件可绑定一个市场仓库的 GitHub Issue，在目录里填 DiscussionIssue 编号。卡片显示评论数和爱心收藏数，用户通过 GitHub 评论或收藏。遇到问题，可以下架对应版本；作者修好后用新版本重新投稿。

软件内投稿可以后续再做。第一步可以先做「我要投稿」按钮，打开 GitHub 投稿页并引导作者准备上面的资料。等投稿量起来，再考虑在鲸鲸内接收 ZIP 和显示审核进度。

## Api 2 · 功能工具

新工具可在清单填写 `Api: 2`。WebAssembly 仍导出 `run() -> i32`，通过 `whale.output_byte(i32)` 逐字节输出 UTF-8 文本，最多 64 KiB，返回 0 表示成功。原有的输入字节接口继续可用。

需要消息汇总时，清单填写 `HostAction: chat.summary`。用户每次选择今天或昨天并确认。鲸鲸用当前模型整理本机该日期内可用的群聊和私聊片段，插件只收到汇总后的文字。云端模型会收到参与汇总的片段，调用可能产生费用。

Api 2 当前供兼容测试版本地试装。公开上架须有支持所需能力的正式客户端、独立的 `index-v2.json` 和覆盖该目录的市场 CI。原有 `index.json` 继续服务 Api 1 工具。定时、原始聊天记录、接管汇总逻辑、微信发送和修改设置需要各自的接口。
