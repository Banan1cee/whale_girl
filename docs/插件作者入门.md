# 鲸鲸插件作者入门

本指南面向第一次写鲸鲸插件的人：按顺序照做即可完成一个可安装、可启用、可自测的包。协议细节、完整能力表和失败码在[插件协议](插件协议.md)；本指南只给可执行配方和预期输出。

适用版本：鲸鲸 4.3.0 及以后；协议 `whale-plugin/1`。旧 Api 1/2/3/4 可执行插件已停用，纯数据人设包仍可安装。

## 0. 先看清边界：插件不监听、不探测端口

- 鲸鲸内核是**本机 HTTP 服务**：host 默认 `127.0.0.1`、端口默认 `8787`（只是默认值，内核默认只绑定回环地址，属仅本机部署；远程访问不是插件能力）。实际监听端口可能因设置或系统分配而不同，内核启动后会把它写进 `data/server-port.txt`，桥接读该文件；启动器通过本机回环接口与内核通信。
- 桥接是**客户端进程**：它主动连内核、操作微信窗口，没有给插件连接用的端口。
- 插件不需要、也不应该监听端口或扫描本机端口。0 级是纯数据主题，没有执行体；1–3 级是受限 Wasm，没有网络能力；Node（4 级）虽然能联网，但宿主能力是通过注入的 `host.call(能力名, 输入)` 走进程内 IPC，插件不要自己起 HTTP 服务，也不要把 `/api/plugins/run` 或其它 `/api/*` 当成插件 SDK。
- 插件与用户的交互只有：清单声明的 provider（手动运行、回复增强/接管、定时任务）和已授权的宿主能力。不要给插件加左侧入口或页面。

## 1. 选等级

| 等级 | 入口 | 运行时 | 能做什么 | 授权 |
| --- | --- | --- | --- | --- |
| 0 | `theme.json` | `theme-data` | 纯数据主题，只改启动器外观 | 无 |
| 1 | `plugin.wasm` | `wasm-restricted` | 手动整数工具 `tool.run@1` | 无 |
| 2 | `plugin.wasm` | `wasm-restricted` | 手动文本工具 `tool.run@1` | 无 |
| 3 | `plugin.wasm` | `wasm-restricted` | 文本工具 + 回复草稿增强 `chat.reply@1`；可申请当前聊天最近 12 条或系统提示词 | 启用时确认聊天访问 |
| 4 | `plugin.js` | `node-full` | 现有扩展点 + 声明的宿主能力 `calls` | 启用时确认完整系统权限 |

包结构固定：ZIP 根目录只有 `plugin.json` 和该等级的一个入口文件。不要把 README、源码、密钥打进安装包。

## 2. 准备工具链

需要 Node.js 18 及以上；不需要安装依赖。在仓库根目录执行：

```text
npm run plugin -- init <id> --template <模板>
npm run plugin -- validate <项目目录或ZIP>
npm run plugin -- test <项目目录或ZIP>
npm run plugin -- pack <项目目录> --out dist/<id>.zip
npm run plugin -- trial <项目目录或ZIP>
```

模板与等级：

| 模板 | 等级 | 说明 |
| --- | --- | --- |
| `integer-tool` | 1 | 生成最小 Wasm 整数工具 |
| `tool` | 2 | 生成最小 Wasm 文本工具 |
| `reply-wasm` | 3 | Wasm 回复草稿增强 |
| `reply-enhancer` | 4 | Node 回复增强 |
| `chat-takeover` | 4 | Node 全聊天接管 |
| `scheduled-task` | 4 | Node 定时任务，带 `status.read@1` 调用示例 |

`validate`、`test` 只读、可重复运行（不写文件）；`trial` 也是静态检查。三者都不执行插件代码、不安装、不授权。`pack` 才会写 ZIP。`trial` 只是模拟路由与权限，`executed` / `installed` / `authorizationGranted` 恒为 `false`。手动工具只有在启动器卡片点「运行一次」时才真正执行并产生输出。

## 3. 配方 A：Node 手动工具（4 级）

这条闭环**不需要 WABT**：先用 CLI 生成 Node 骨架，再把两个文件替换成本节示例（README 不会被装进包）。

```text
node scripts/plugin-cli.js init demo-node-tool --template scheduled-task
```

预期（CLI 在当前目录创建 `demo-node-tool/`；不要先手动建同名目录，已存在会失败）：

```json
{ "ok": true, "directory": "demo-node-tool", "template": "scheduled-task" }
```

把 `plugin.json` 与 `plugin.js` 替换为下面两份。

`plugin.json`：

```json
{
  "format": "whale-plugin/1",
  "level": 4,
  "id": "demo-node-tool",
  "name": "演示工具",
  "author": "Your Name",
  "version": "1.0.0",
  "minAppVersion": "4.3.0",
  "description": "统计输入文本字数，并可选读取宿主状态",
  "entry": "plugin.js",
  "runtime": "node-full",
  "provides": {
    "tool.run@1": { "mode": "tool", "scope": "manual" }
  },
  "calls": ["status.read@1"]
}
```

`plugin.js`（不要用模板字符串，保持普通字符串拼接）：

```js
'use strict';

exports.providers = {
  'tool.run@1': async (input, { host }) => {
    if (input?.action === 'status') return host.call('status.read@1', {});
    const text = typeof input?.text === 'string' ? input.text : '';
    return { characters: [...text].length };
  },
};
```

在仓库根目录依次执行（路径按你的实际目录替换）：

```text
node scripts/plugin-cli.js validate demo-node-tool
node scripts/plugin-cli.js test demo-node-tool
node scripts/plugin-cli.js pack demo-node-tool --out demo-node-tool.zip
node scripts/plugin-cli.js trial demo-node-tool.zip
```

`validate` 预期：

```json
{
  "ok": true,
  "id": "demo-node-tool"
}
```

`test` 预期：

```json
{
  "ok": true,
  "id": "demo-node-tool",
  "executed": false,
  "syntaxChecked": true
}
```

`pack` 预期（filename 取决于 --out）：

```json
{
  "ok": true,
  "id": "demo-node-tool",
  "filename": "demo-node-tool.zip"
}
```

`trial` 预期（模拟，不执行；字段可能更多）：

```json
{
  "ok": true,
  "id": "demo-node-tool",
  "simulated": true,
  "executed": false,
  "installed": false,
  "authorizationGranted": false,
  "level": 4,
  "permissionName": "4 级 · Node.js（完整系统权限）",
  "nodeAccessConfirmationRequired": true,
  "chatConsentRequired": false,
  "routes": [
    { "capability": "tool.run@1", "mode": "tool", "scope": "manual" }
  ],
  "calls": [
    { "capability": "status.read@1", "status": "declared", "requiresConsent": false }
  ]
}
```
运行结果闭环（4 级插件需要内核与总开关）：先在插件市场顶部勾选「启用统一协议插件」并启动内核；再「从本地安装」选 ZIP，在「已安装」卡片启用并确认完整系统权限；点「设置 → 运行一次」，输入 `{"text":"你好"}`，预期得到 `{"characters":2}`；输入 `{"action":"status"}` 会调用 `status.read@1`，预期得到 `{"version":"4.3.0","running":true,"pluginProtocol":"whale-plugin/1"}`（字段固定为 version / running / pluginProtocol）。注意：上面 CLI 的 `test` / `trial` 都不执行 `plugin.js`，真实输出只来自这一步；WABT 只在配方 B 自定义 Wasm 时才需要。

## 4. 配方 B：Wasm 整数工具（1 级）

最简单的方式让 CLI 生成一个能通过校验的最小模块：

```text
node scripts/plugin-cli.js init demo-int --template integer-tool
node scripts/plugin-cli.js validate demo-int
node scripts/plugin-cli.js trial demo-int
```

预期：

```json
{ "ok": true, "directory": "demo-int", "template": "integer-tool" }
```

```json
{ "ok": true, "id": "demo-int" }
```

```json
{
  "ok": true,
  "id": "demo-int",
  "simulated": true,
  "executed": false,
  "installed": false,
  "authorizationGranted": false,
  "level": 1,
  "permissionName": "1 级 · 受限 Wasm（整数工具）",
  "nodeAccessConfirmationRequired": false,
  "chatConsentRequired": false,
  "routes": [
    { "capability": "tool.run@1", "mode": "tool", "scope": "manual" }
  ],
  "calls": []
}
```

要写自己的逻辑，把 `demo-int/plugin.wasm` 换成你编译的模块。需要 WABT 的 `wat2wasm`：从 WABT 官方发布页下载，或 `npm install -g wabt` 安装；装完先跑 `wat2wasm --version` 确认命令可用（应输出版本号）。完整可复制的 `tool.wat`（导出 `run`，返回整数 42）：

```wat
(module
  (func (export "run") (result i32)
    i32.const 42))
```

编译并替换：

```text
wat2wasm tool.wat -o demo-int/plugin.wasm
node scripts/plugin-cli.js test demo-int
node scripts/plugin-cli.js pack demo-int --out demo-int.zip
```

预期 `test`：

```json
{
  "ok": true,
  "id": "demo-int",
  "executed": false,
  "syntaxChecked": true
}
```

Wasm 的导入/导出契约（`whale_plugin` 的 `input_size` / `input_byte` / `output_byte`，以及 3 级回复的 JSON 输入输出）见[插件协议](插件协议.md)的「Wasm 入口」一节。1 级用 `run` 的整数返回值；2–3 级必须返回 0，并逐字节输出 UTF-8。

## 5. 配方 C：纯数据主题（0 级）

建立 `demo-theme/`，只有两个文件。

`plugin.json`：

```json
{
  "format": "whale-plugin/1",
  "level": 0,
  "id": "demo-theme",
  "name": "演示主题",
  "author": "Your Name",
  "version": "1.0.0",
  "minAppVersion": "4.3.0",
  "description": "仅改启动器外观，无执行体",
  "entry": "theme.json",
  "runtime": "theme-data",
  "provides": {},
  "calls": []
}
```

`theme.json`：

```json
{
  "schema": 1,
  "id": "demo-theme",
  "name": "演示主题",
  "author": "Your Name",
  "version": "1.0.0",
  "colors": {
    "accent": "#6FD6C0",
    "background": "#07120F",
    "surface": "#101B18",
    "text": "#F2FAF7",
    "muted": "#9FB3AD",
    "border": "#243140",
    "field": "#0C1714"
  },
  "font": { "family": "Microsoft YaHei UI", "scale": 1.05 },
  "metrics": { "corner": 12, "spacing": 1.05 },
  "dialog": { "surface": "#101B18", "border": "#243140", "corner": 12 }
}
```

校验与打包：

```text
node scripts/plugin-cli.js validate demo-theme
node scripts/plugin-cli.js test demo-theme
node scripts/plugin-cli.js pack demo-theme --out demo-theme.zip
node scripts/plugin-cli.js trial demo-theme.zip
```

预期：

```json
{ "ok": true, "id": "demo-theme" }
```

```json
{ "ok": true, "id": "demo-theme", "executed": false, "syntaxChecked": true }
```

```json
{ "ok": true, "id": "demo-theme", "filename": "demo-theme.zip" }
```

```json
{
  "ok": true,
  "id": "demo-theme",
  "simulated": true,
  "executed": false,
  "installed": false,
  "authorizationGranted": false,
  "level": 0,
  "permissionName": "0 级 · 纯数据主题（无执行体、无权限）",
  "nodeAccessConfirmationRequired": false,
  "chatConsentRequired": false,
  "routes": [],
  "calls": []
}
```

主题规则：`theme.json` 的 `id` 必须等于清单 `id`；顶层只允许 `schema/id/name/author/version/colors/font/metrics/dialog`；颜色只认 7 个语义键；字体只能取内置白名单；缩放 0.85–1.15、圆角 0–24；文件不超过 64 KiB。**CLI 的 `validate` / `test` / `pack` 只查结构、大小、`schema:1` 和 `id`**，不检查颜色/字体/数值，也不检查最低客户端版本；这些由启动器在安装/读取包时校验（含 0 级最低 4.3.0），启用时再校验最终对比度，不达标不会应用。CLI 通过不等于能启用。

主题**不包含页面样式**：页面密度/字号和区块显隐是启动器自己的 `data/launcher-pages.json`（「设置 → 外观 → 页面样式」导入），不随插件包分发。

## 6. 安装、启用、更新、卸载

1. 前置：可执行插件（1–4 级）在安装前就先在插件市场顶部勾选「启用统一协议插件」并启动内核；0 级主题不需要总开关或内核。
2. 启动器「插件市场 → 从本地安装」选 ZIP；确认框会显示作者、版本、声明的 provider 和 `calls`。
3. 在「已安装」卡片上启用，并按等级确认：
   - 0 级：启用即应用外观，不需要授权，也没有额外权限确认；
   - 1–2 级：仍需启用；启用会写入授权记录，但没有额外聊天或系统权限弹窗；
   - 3 级：只有声明 `chat.reply@1` 时才确认聊天访问；只做文本工具则没有额外确认；
   - 4 级：确认完整系统权限（不是沙箱，以当前 Windows 用户身份运行）。
4. 手动工具（1–4 级，凡声明 `tool.run@1`）在卡片「设置」里输入 JSON 后点「运行一次」；回复增强/接管/定时任务由宿主在对应时机调用。
5. 修改设置会重新签发授权，旧代次的迟到结果会被丢弃；停用会撤销授权并终止运行中的任务。
6. 同一 ID 更新必须升版本、保持作者一致；更新后需要重新启用，设置保留，授权重新签发。
7. 卸载会删除包、授权、设置和该插件的会话状态；已发生的微信副作用无法撤回。

## 7. 宿主能力与授权规则

完整能力表（输入、输出、副作用、是否需要授权、是否对插件开放）在[插件协议](插件协议.md)的「宿主能力全表（仅 4 级）」一节，以 `src/services/pluginProtocolRegistry.json` 为准。写插件前先查表，不要在文档或代码里猜能力名。

几条硬规则：

- `calls` 没声明的能力一律不能调用；声明了但宿主未开放的会标成「宿主未开放」，调用失败。
- 1–3 级 `calls` 必须为空，不能调用宿主能力。
- 写类能力（发送、写记忆、改设置、朋友圈操作等）必须在清单 `calls` 里声明并在启用时授权；确认框会列出这些调用，调用点仍按清单和授权代次复核。撤销授权后调用报 `grant_revoked`。
- `message.send@1` 返回 `queued` / `confirmed:false` 只表示已排队，不是微信已送达；`message.submit@1` 是保留能力，声明了也不会执行。
- 插件不能写 API Key、不能借人设写入切模型、不能指定朋友圈发表账号。
- 失败处理见协议「失败码：先分插件可见与宿主诊断」：Worker 会把多数实现/参数/返回错误统一报成 `host_call_failed`，撤权/超时可能直接终止调用。不要在插件里按内部分发器码分支，也不要盲目重试或重复产生副作用。

## 8. 当前市场与投稿

远端 `Banan1cee/whale-girl-plugins` 目前只发布人设目录 `index-personas.json`，**没有** `index-v5.json`。因此：

- 新协议插件（含主题）只能本地安装试装，不能在启动器市场里浏览/投稿/上架。
- 本地安装成功、`trial` 通过都不代表已审核或已收录。
- 市场仓就绪后的投稿目标固定为 `Banan1cee/whale-girl-plugins:main`，作者交 `plugins/<id>/plugin.json`、`packages/<id>-<version>.zip` 和可审核源码说明；目录和 SHA-256 由市场 CI 生成。

## 9. 自测清单与常见错误

- 正常输入、空输入、超长输入各跑一次；凡声明 `tool.run@1` 的等级都在卡片手动运行并核对返回 JSON。
- 停用后确认不再运行；重新启用后设置还在。
- 改设置后确认旧结果被丢弃。
- 失败时按各能力的实际语义处理：可降级的能力按协议定义回退，接管/生成/写操作按错误处理；核对返回与日志，不要假定统一回退，也不要盲目重试。
- 主题包：未知字段、错误颜色、超限文件应被拒绝；启用后重启仍生效，停用恢复内置外观。

常见错误对照：

| 报错 | 原因 |
| --- | --- |
| `清单无效` / `未知字段` | `plugin.json` 拼错字段或多写了不支持的键 |
| `ZIP 等级入口无效` | 入口文件名与 `level` 不匹配（0 主题、1–3 `plugin.wasm`、4 `plugin.js`） |
| `plugin.wasm ... 导入不符合该等级` | 用了未允许的 Wasm 导入，或不是有效 Wasm |
| `theme.json 必须包含 schema:1 且 id 与插件清单 id 一致` | 主题 `id` 写错或 `schema` 不是 1 |
| `能力未声明` / `host_capability_not_declared` | 调用了没写进 `calls` 的能力 |
| `grant_revoked` | 插件已停用、被更新或授权代次变化 |
| `节点插件需要确认完整系统权限` | 4 级启用时没有确认权限 |
