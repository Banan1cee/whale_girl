# 人设预设（一个风格一个文件）

这里放**可以直接导入的人设**。顶层只保留通用预设，启动器下拉里按每个文件里的 `order` 排序。

| order | 文件 | 风格 |
|---|---|---|
| 0 | `persona-neutral.json` | 通用聊天伙伴：无固定形象与口癖，像熟人一样自然聊天，适合大多数场景 |

## 文件格式

```json
{
  "id": "persona-neutral",
  "order": 0,
  "name": "预设标题（只用于列表展示，不会改她的名字）",
  "description": "这版是什么风格、适合什么时候用",
  "age": 22,
  "privateMaxChars": 120,
  "groupMaxChars": 70,
  "historyTurns": 100,
  "groupHistoryTurns": 60,
  "customPrompt": "完整人设提示词"
}
```

只认上面这些字段，其他字段会被忽略。`id` 只能是小写字母、数字、点、横线、下划线。

- `order` 决定启动器下拉里的**排列位置**（数字小的排前面）；没写 `order` 的排在最后，再按 `version` 比。
- `name` 是**预设标题**（列表里显示的那一行），**不会改她的名字**；真要改名用 `personaName`。但现有预设有测试钉着「预设标题不能当她的名字」，所以都不要写 `personaName`。
- 其余可写字段：`appearance` / `personality` / `background`、`job`、`emoji`（关/少/正常/多）、`maxBubbles`（最多分几条消息，1-8）。
- 4.2 起不再读取 `preset` / `text`（整体语气、具体要求已移除），旧文件里有也只会被忽略。

## 自己保存的预设（4.2 起）

启动器「人设 → 人设预设」里的「另存为预设」会把当前人设写到 `data/personas/<id>.json`，`id` 由程序生成（`user-…`），标题只作为列表显示，不参与文件路径。

- 保存后立即出现在下拉最上面，并成为「当前来源」；之后每次保存人设都会自动回写这条预设。
- 内置和插件市场预设是只读身份设定：应用后名字、年龄、职业、外观、性格、背景和自定义提示词锁定；字数、上下文、颜文字和开关仍可调。要改身份设定，点「复制为自建预设」生成副本。
- 自建预设支持「更新此预设」「重命名」；删除时直接删文件。
- 「删除预设」：内置和插件市场预设只写进 `data/personas/_hidden.json` 隐藏，不删安装目录和插件文件。插件卸载后重新安装、文件内容或时间变化时，隐藏标记会自动失效并恢复显示。
- 正在使用的预设不能删除；先导入其他预设再删。
- 人设页没有「全部保存」按钮：修改后失焦即自动保存。
- 备份/恢复会把 `data/personas/` 一起打包。

> `data/personas/` 属于用户数据，不会进发行包，也不应该手工拷进 `assets/personas/`。

## 怎么用

1. **启动器**：左栏「人设」→「人设预设」下拉选一版 →【导入这版】
2. **接口**：`POST /api/persona/preset`，body `{"id":"persona-neutral"}`
3. **手动**：把人设内容粘进「人设 → 身份 → 自定义提示词」

导入只会改人设相关设置，不动模型、Key、群配置和记忆。

> 注意：`assets/personas/` 里只能放通用内容。**不要**写主人的微信号、群成员真名、API Key——这个目录是跟着发行包发出去的。角色专属内容统一放 `legacy/`，需要时再手动复制回顶层。

## 写新预设的约定

1. **`customPrompt` 最多 6000 字**（`src/persona/presets.js` 的 `toPatch` 会截断）。超长的原文要么精简后再放，要么指出要保留的部分。
2. **必须写「可以发语音」**：默认写「默认发文字；对方明确要你发语音时，直接正常答应……别自称没有麦克风」。少这一句她会回「我没麦克风，发不了语音」。
3. 群友原文里的 `QQ` 之类平台名改成本项目的「微信」，其余措辞尽量别动——那是人家的风格。
4. 群友发来的原创，`description` 里注明「群友自定义」，不要改人家的人设内核。
5. 角色专属、只在本机娱乐的预设放 `legacy/`，不要放顶层；确有必要随包时再单独评估发行范围。
